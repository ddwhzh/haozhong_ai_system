## 1. 概述

### 1.1 设计目标

评估Agent采用基于匈牙利匹配的自动化评估架构, 旨在解决传统向量检索在细粒度相似度判别和对称性方面的不足. 核心设计理念包括:

1. **混合评分机制**: 结合密集向量和稀疏矩阵的优势
2. **最优匹配算法**: 使用匈牙利算法进行二部图最优分配
3. **自动化优化**: 基于评估反馈自动生成提示词改进建议

### 1.2 架构原则

- **模块化设计**: 评分、匹配、优化功能独立封装
- **可扩展性**: 支持自定义评分函数和匹配策略
- **可观测性**: 完整的日志和追踪支持
- **异步优先**: 所有I/O操作采用异步模式

### 2.2 模块结构

#### 2.2.1 EvaluationAgent (`agent.py`)
**职责**: Agent入口点, 协调整个评估流程

**主要方法**:
- `_execute()`: 执行评估管道
- `_prepare_for_matching()`: 准备节点数据 (嵌入、分词)

**依赖**:
- `ScoringFunction`: 评分计算
- `HungarianMatcher`: 匹配算法
- `AutoPromptOptimizer`: 提示词优化

#### 2.2.2 ScoringFunction (`scoring.py`)
**职责**: 混合评分函数实现

**核心组件**:
- `_denoised_cosine()`: 带去噪的余弦相似度
- `_sparse_score()`: BM25风格稀疏评分
- `score()`: 混合评分计算
- `batch_score()`: 批量评分矩阵计算

**关键参数**:
- `sparse_weight`: 稀疏评分权重 (默认0.3)
- `denoising_strength`: 去噪强度 (默认0.1)

#### 2.2.3 HungarianMatcher (`hungarian_matcher.py`)
**职责**: 二部图最优匹配

**核心组件**:
- `match()`: 执行匈牙利匹配
- `evaluate_faithfulness()`: 忠实度评估

**算法**:
- 使用 `scipy.optimize.linear_sum_assignment` 求解最优分配
- 成本矩阵 = 1 - 相似度分数

#### 2.2.4 AutoPromptOptimizer (`auto_prompt.py`)
**职责**: 自动提示词优化

**核心组件**:
- `optimize()`: 生成优化建议
- `_identify_weak_sections()`: 识别弱项片段
- `_generate_optimizations()`: LLM生成优化建议

**触发条件**: 整体评分 < `EVALUATION_CONFIDENCE_THRESHOLD`

## 3. 数据流

### 3.1 评估流程数据流

```
1. Input: AgentInput
   └─> evidence_graph: EvidenceGraph
       ├─> generated_nodes (content_type="generated_content")
       └─> evidence_nodes (content_type in ["fused_evidence", "document_chunk", "kg_match", "reasoning_chain"])

2. Prepare for Matching
   └─> For each node:
       ├─> Extract content
       ├─> Tokenize (lowercase split)
       └─> Generate embedding (via OpenAIEmbeddings)

3. Scoring
   └─> ScoringFunction.batch_score()
       ├─> Dense score: _denoised_cosine(embedding_a, embedding_b)
       ├─> Sparse score: _sparse_score(tokens_a, tokens_b)
       └─> Combined: alpha * dense + (1-alpha) * sparse
       └─> Output: score_matrix (n_generated × n_evidence)

4. Hungarian Matching
   └─> HungarianMatcher.match()
       ├─> cost_matrix = 1.0 - score_matrix
       ├─> linear_sum_assignment(cost_matrix)
       └─> Output: matches, unmatched_preds, unmatched_targets

5. Faithfulness Evaluation
   └─> HungarianMatcher.evaluate_faithfulness()
       ├─> For each match: is_faithful = score >= threshold
       ├─> faithfulness_rate = faithful_count / total
       └─> Output: evaluation_result dict

6. Create Evaluation Node
   └─> evidence_graph.add_evidence()
       ├─> Evidence(content_type="evaluation_result")
       ├─> Belief(confidence=overall_score)
       └─> Intent(intent_type=EVALUATE)

7. Update Beliefs
   └─> For each section_score:
       └─> BeliefUpdate(target_belief_id, new_confidence)

8. Auto Prompt Optimization (if overall_score < threshold)
   └─> AutoPromptOptimizer.optimize()
       ├─> Identify weak sections
       ├─> Generate optimization proposals (via LLM)
       └─> Create prompt_optimization nodes

9. Output: AgentOutput
   └─> new_nodes: [evaluation_node, ...prompt_nodes]
   └─> belief_updates: [BeliefUpdate, ...]
   └─> metrics: {overall_score, faithfulness_rate, ...}
```

## 4. 评分机制详解

### 4.1 混合评分公式

```
hybrid_score = α × dense_score + (1 - α) × sparse_score

其中:
- α = dense_weight = 1 - sparse_weight (默认0.7)
- sparse_weight = EVALUATION_SPARSE_WEIGHT (默认0.3)
```

### 4.2 密集评分 (Dense Score)

**算法**: 带自监督去噪的余弦相似度

**步骤**:
1. 计算平均向量: `mean_vec = (embedding_a + embedding_b) / 2`
2. 估计噪声方向: `noise_direction = mean_vec / ||mean_vec||`
3. 去噪: 
   - `a_denoised = a - λ × (a · noise_direction) × noise_direction`
   - `b_denoised = b - λ × (b · noise_direction) × noise_direction`
   - 其中 `λ = denoising_strength` (默认0.1)
4. 计算余弦相似度: `cos(a_denoised, b_denoised)`

**优势**: 提高信号噪声比, 增强区分度

### 4.3 稀疏评分 (Sparse Score)

**算法**: BM25风格的词项重叠评分

**公式**:
```
sparse_score = Σ IDF(q_i) × TF_norm(q_i, doc)

其中:
- IDF(q_i) = log(1 + 1 / query_tf(q_i))
- TF_norm = (tf × (k1 + 1)) / (tf + k1 × (1 - b + b × doc_len / avg_dl))
- k1 = 1.2, b = 0.75 (BM25标准参数)
```

**关键特性**:
- **非对称性**: `score(query, doc) ≠ score(doc, query)`
- **归一化**: 最终分数归一化到 [0, 1] 区间

**优势**: 打破对称性, 提供细粒度匹配信号

## 5. 匈牙利匹配算法

### 5.1 算法概述

匈牙利算法用于解决二部图最优分配问题. 在评估场景中:

- **左侧节点**: 生成内容片段 (predictions)
- **右侧节点**: 证据源 (targets)
- **边权重**: 相似度分数 (score)

**目标**: 找到最优匹配, 使得总相似度最大 (或总成本最小)

### 5.2 算法流程

```
1. 构建分数矩阵 (score_matrix)
   - 维度: n_generated × n_evidence
   - 元素: ScoringFunction.batch_score() 的结果

2. 转换为成本矩阵 (cost_matrix)
   - cost_matrix = 1.0 - score_matrix
   - 匈牙利算法最小化成本, 等价于最大化相似度

3. 执行线性分配 (linear_sum_assignment)
   - 输入: cost_matrix
   - 输出: row_indices, col_indices (匹配对)

4. 构建匹配结果
   - matches: [(pred_idx, target_idx, score), ...]
   - unmatched_preds: 未匹配的生成片段索引
   - unmatched_targets: 未匹配的证据源索引

5. 计算整体评分
   - overall_score = Σ match_scores / max(len(matches), 1)
```

### 5.3 复杂度分析

- **时间复杂度**: O(n³), 其中 n = max(n_generated, n_evidence)
- **空间复杂度**: O(n²), 用于存储分数矩阵

### 5.4 边界情况处理

- **空输入**: 返回空匹配结果, overall_score = 0
- **非方阵**: `linear_sum_assignment` 自动处理矩形矩阵
- **全零分数**: 所有匹配分数为0, 所有项标记为未匹配

## 6. 忠实度评估

### 6.1 评估指标

#### 忠实度率 (Faithfulness Rate)
```
faithfulness_rate = faithful_count / total_generated_sections

其中:
- faithful_count: 匹配对中 score >= threshold 的数量
- total_generated_sections: 生成片段总数
- threshold: EVALUATION_CONFIDENCE_THRESHOLD (默认0.7)
```

#### 完整性率 (Completeness Rate)
```
completeness_rate = matched_targets / total_evidence_sources

其中:
- matched_targets: 被匹配的证据源数量
- total_evidence_sources: 证据源总数
```

### 6.2 片段级评估

每个生成片段获得:
- `generated_idx`: 生成片段索引
- `evidence_idx`: 匹配的证据源索引
- `score`: 匹配分数
- `is_faithful`: 是否忠实 (score >= threshold)

## 7. 自动提示词优化

### 7.1 触发条件

```
if overall_score < EVALUATION_CONFIDENCE_THRESHOLD:
    trigger_auto_prompt_optimization()
```

### 7.2 优化流程

```
1. 识别弱项片段
   └─> _identify_weak_sections()
       ├─> score < 0.5 的片段
       ├─> is_faithful = False 的片段
       └─> unmatched_sections (未匹配的片段)

2. 生成优化建议
   └─> _generate_optimizations()
       ├─> 构建LLM提示词
       │   ├─> System: auto_prompt_system.md
       │   └─> Human: weak_sections + current_prompts
       ├─> 调用LLM生成JSON格式建议
       └─> 解析为优化提案列表

3. 创建优化节点
   └─> evidence_graph.add_evidence()
       ├─> Evidence(content_type="prompt_optimization")
       ├─> Belief(confidence=expected_improvement)
       └─> Intent(intent_type=OPTIMIZE_PROMPT)
```

### 7.3 优化提案结构

```json
{
    "diagnosis": "问题诊断 (如: hallucination, missing context)",
    "prompt_patch": "具体的提示词修改建议",
    "expected_improvement": 0.0-1.0,
    "target": "目标提示词 (system_prompt, proposal_template, ...)"
}
```

## 9. 错误处理

### 9.1 异常场景

1. **无生成内容**
   - 返回 `AgentStatus.NEEDS_MORE_INFO`
   - 错误消息: "No generated content to evaluate"

2. **嵌入生成失败**
   - 使用空嵌入向量 `[]`
   - 记录警告日志
   - 继续执行 (稀疏评分仍可用)

3. **LLM调用失败**
   - 记录错误日志
   - 返回空优化提案列表
   - 不影响评估结果

4. **JSON解析失败**
   - 将原始内容作为 `prompt_patch`
   - 设置默认 `expected_improvement = 0.3`
   - 记录警告日志

### 9.2 日志规范

所有日志遵循项目规范:
- 使用 `structlog` 进行结构化日志
- 事件名称使用 `lowercase_with_underscores` 格式
- 关键操作记录: `evaluation_pipeline_start`, `hungarian_matching_complete`, `auto_prompt_triggered`

## 10. 性能优化

### 10.1 批量处理

- `batch_score()`: 批量计算分数矩阵, 避免循环调用
- 异步嵌入生成: 使用 `aembed_query()` 进行异步I/O

### 10.2 矩阵运算优化

- 使用 `numpy` 进行向量化计算
- 预分配矩阵内存
- 避免不必要的矩阵复制

### 10.3 缓存策略

- 嵌入向量可缓存 (相同内容)
- 评分结果可缓存 (相同输入对)
