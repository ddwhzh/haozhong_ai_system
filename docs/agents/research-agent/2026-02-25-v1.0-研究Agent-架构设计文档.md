## 1. 概述

### 1.1 设计目标

研究Agent采用 **7阶段迭代闭环架构**, 通过以下设计实现全自动化研究:

1. **领域探索**: Web搜索 + LLM分析, 建立领域认知
2. **多源文献检索**: arXiv + Semantic Scholar + Brave, 覆盖学术与产业
3. **知识综合与假设生成**: LLM驱动的gap分析和hypothesis formulation
4. **实验设计与代码生成**: LLM生成可执行Python实验代码
5. **沙箱隔离执行**: Docker/subprocess沙箱, 资源受限
6. **结果分析与假设验证**: 量化指标解析 + LLM定性分析
7. **迭代决策**: iterate/pivot/conclude三路由收敛控制

### 1.2 核心设计理念

- **Closed-loop Research**: 每次迭代的实验结果反馈到下一轮文献检索和假设修正
- **Evidence-based Hypothesis**: 假设必须有文献支撑, 实验必须有量化指标
- **Bounded Iteration**: 硬限制最大迭代次数 (默认5), 防止无限循环
- **Isolation**: 实验代码在沙箱中隔离执行, 不影响宿主系统
- **Independence**: ResearchGraph 与主 PipelineGraph 完全隔离, 复用基础设施不耦合业务

## 3. 数据流设计

### 3.1 完整数据流

```
1. Input: ResearchStartRequest
   ├── topic: str                    # 研究课题
   └── max_iterations: int           # 最大迭代次数 (默认5)

2. Phase 1: Domain Scout
   ├── Input: research_topic
   ├── Process:
   │   ├── Brave Web Search (3个查询变体)
   │   ├── 去重 (URL级)
   │   └── LLM分析 → 提取领域上下文
   └── Output:
       ├── domain_context: {keywords, directions, core_problems, refined_queries}
       └── journal_entry: JournalEntry

3. Phase 2: Literature Survey
   ├── Input: research_topic + domain_context.refined_queries
   ├── Process:
   │   ├── arXiv API检索 (每个query)
   │   ├── Semantic Scholar API检索 (每个query)
   │   ├── 去重 (DOI > arXiv ID > 标题)
   │   └── LLM相关性评估
   └── Output:
       ├── papers: List[Paper] (去重, 按相关性排序)
       ├── survey_assessment: {paper_assessments, common_themes, gaps}
       └── journal_entry: JournalEntry

4. Phase 3: Knowledge Synthesis
   ├── Input: research_topic + domain_context + papers + survey_assessment
   ├── Process:
   │   ├── LLM综合Top 20论文
   │   ├── 识别矛盾 + gap
   │   └── 生成testable hypotheses
   └── Output:
       ├── synthesis_report: str
       ├── hypotheses: List[Hypothesis] (状态=proposed)
       └── journal_entry: JournalEntry

5. Phase 4: Experiment Design
   ├── Input: hypotheses[0] (首个可测试假设) + research_topic
   ├── Process:
   │   └── LLM生成实验方案 + Python代码
   └── Output:
       ├── experiment: Experiment (含code, dependencies, metrics)
       ├── hypotheses: [更新状态为testing]
       └── journal_entry: JournalEntry

6. Phase 5: Experiment Execution
   ├── Input: experiment.code + experiment.dependencies
   ├── Process:
   │   ├── SandboxEngine.execute()
   │   │   ├── 检查Docker可用性
   │   │   ├── Docker执行 / subprocess fallback
   │   │   └── 捕获stdout/stderr/exit_code
   │   └── 解析JSON metrics
   └── Output:
       ├── experiment: Experiment (含result)
       └── journal_entry: JournalEntry

7. Phase 6: Result Analysis
   ├── Input: experiment (含result) + hypothesis
   ├── Process:
   │   └── LLM分析结果 vs 假设
   └── Output:
       ├── analysis_report: str
       ├── hypothesis_update: Hypothesis (状态=confirmed/rejected/inconclusive)
       ├── improvement_suggestions: List[str]
       └── journal_entry: JournalEntry

8. Phase 7: Iteration Decision
   ├── Input: 全部研究状态摘要
   ├── Process:
   │   └── LLM决策 iterate/pivot/conclude
   └── Output:
       ├── decision: ResearchDecision
       ├── iteration_record: IterationRecord
       ├── final_report: str (仅conclude时)
       └── journal_entry: JournalEntry

9. Post-Decide Routing:
   ├── iterate → current_phase=SURVEY, iteration_count++
   ├── pivot → current_phase=SCOUT, iteration_count++
   └── conclude → current_phase=CONCLUDE → report_assembly → END
```

### 3.2 ResearchState 更新流程

```
初始 ResearchState
    │
    ├─▶ Scout
    │   └─▶ 更新: domain_context, +journal_entry
    │
    ├─▶ Survey
    │   └─▶ 更新: +literature (reducer去重), metadata.survey_assessment, +journal_entry
    │
    ├─▶ Synthesize
    │   └─▶ 更新: +hypotheses (reducer按ID合并), synthesis_report, +journal_entry
    │
    ├─▶ Design
    │   └─▶ 更新: +experiments (reducer按ID合并), hypotheses[0].status=testing, +journal_entry
    │
    ├─▶ Experiment
    │   └─▶ 更新: experiments[-1].result + status, +journal_entry
    │
    ├─▶ Analyze
    │   └─▶ 更新: hypotheses[i].status/confidence, analysis_report, +journal_entry
    │
    ├─▶ Decide
    │   └─▶ 更新: +iteration_history, +journal_entry, (final_report if conclude)
    │
    └─▶ Conclude
        └─▶ 更新: final_report (完整报告), +journal_entry
```

## 4. 状态机设计

### 4.1 ResearchPhase枚举

| Phase | 值 | 说明 | 下一阶段 |
|-------|-----|------|---------|
| SCOUT | "scout" | 领域探索 | SURVEY |
| SURVEY | "survey" | 文献检索 | SYNTHESIZE |
| SYNTHESIZE | "synthesize" | 知识综合 | DESIGN |
| DESIGN | "design" | 实验设计 | EXPERIMENT |
| EXPERIMENT | "experiment" | 实验执行 | ANALYZE |
| ANALYZE | "analyze" | 结果分析 | DECIDE |
| DECIDE | "decide" | 迭代决策 | SURVEY / SCOUT / CONCLUDE |
| CONCLUDE | "conclude" | 报告生成 | END |

### 4.2 迭代决策路由

| 决策 | 目标Phase | 条件 |
|------|----------|------|
| iterate | SURVEY | 结果有改进空间, 有未探索角度 |
| pivot | SCOUT | 当前方向不产出, 需要换方向 |
| conclude | CONCLUDE | 假设已充分验证 / 达到max_iterations / 改进幅度<5% |

### 4.3 安全约束

- **iteration_count > max_iterations**: 强制 conclude
- **所有阶段异常**: 记录error journal, 不中断流程

## 5. Reducer设计

### 5.1 Paper去重Reducer (_merge_papers)

```
合并策略: DOI优先 > arXiv ID > 标题 (小写) 作为去重key
- 已存在的key不再添加
- 保留首次出现的Paper实例
```

### 5.2 Hypothesis合并Reducer (_merge_hypotheses)

```
合并策略: 按hypothesis_id合并
- 相同ID: 用新值覆盖 (更新status/confidence)
- 不同ID: 追加
```

### 5.3 Experiment合并Reducer (_merge_experiments)

```
合并策略: 按experiment_id合并
- 相同ID: 用新值覆盖 (更新status/result)
- 不同ID: 追加
```

### 5.4 Journal/Iteration追加Reducer

```
合并策略: 直接append
- research_journal: 按时间顺序追加
- iteration_history: 按迭代轮次追加
```

## 6. 外部服务集成

### 6.1 ArxivClient

**协议**: arXiv REST API (Atom XML feed)  
**端点**: `https://export.arxiv.org/api/query`  
**认证**: 无需API key  
**限流**: arXiv自身限流 (建议间隔3秒)

**返回字段**: title, authors, abstract, year, url, arxiv_id, categories, pdf_url

### 6.2 SemanticScholarClient

**协议**: Semantic Scholar Academic Graph API (JSON)  
**端点**: `https://api.semanticscholar.org/graph/v1/paper/search`  
**认证**: 可选API key (`RESEARCH_S2_API_KEY`), 无key限流严格  
**限流**: 无key 100 req/5min, 有key 1 req/sec

**返回字段**: title, authors, abstract, year, url, doi, arxiv_id, citation_count, fieldsOfStudy  
**额外能力**: get_citations(), get_references() — 论文引用图谱

### 6.3 BraveSearchClient

**复用**: 与检索Agent共享同一客户端实例  
**用途**: 领域探索阶段的Web搜索

## 7. 沙箱引擎设计

### 7.1 执行策略

```
Docker可用?
├── 是 → Docker容器隔离执行
│   ├── 创建临时目录, 写入experiment.py + setup.sh
│   ├── docker run --rm --memory=2g --cpus=1 --network=none
│   ├── 挂载临时目录到/workspace
│   └── 捕获stdout/stderr/exit_code
└── 否 → subprocess fallback
    ├── pip install dependencies
    ├── python experiment.py
    └── 捕获stdout/stderr/exit_code
```

### 7.2 资源限制

| 资源 | Docker模式 | subprocess模式 |
|------|-----------|---------------|
| CPU | `--cpus=1` | 无限制 |
| 内存 | `--memory=2g` | 无限制 |
| 超时 | asyncio.wait_for(300s) | asyncio.wait_for(300s) |
| 网络 | `--network=none` | 无限制 |

### 7.3 输出解析

- **metrics**: 从stdout最后一行JSON解析, 格式为 `{"metric_name": value, ...}`
- **output_files**: 预留接口, 当前不实现
- **stdout/stderr**: 截断到10000/5000字符, 防止内存溢出

## 11. 错误处理设计

### 11.1 各阶段异常处理

**统一策略**: 每个阶段的异常都被catch, 记录error journal entry, 不中断流程.

| 阶段 | 异常场景 | 处理 | 影响 |
|------|---------|------|------|
| Scout | Brave API超时/LLM失败 | 返回空domain_context | Survey用topic作为fallback query |
| Survey | arXiv/S2 API失败 | 跳过失败源, 保留成功源结果 | 论文数量减少 |
| Synthesize | LLM失败 | 返回空hypotheses | Design阶段无假设可测试 |
| Design | LLM生成无效代码 | 返回含错误代码的Experiment | Experiment阶段执行失败 |
| Experiment | 沙箱超时/崩溃 | 返回timeout/failed状态 | Analyze分析失败结果 |
| Analyze | LLM失败 | 返回inconclusive状态 | Decide倾向conclude |
| Decide | LLM失败 | 强制conclude | 结束研究循环 |

### 11.2 LLM JSON解析容错

所有Agent统一使用 `_parse_json_response()`:
1. 去除markdown代码块围栏 (` ```json ... ``` `)
2. 尝试 `json.loads()`
3. 失败时返回含原始文本的fallback dict
4. 记录warning日志

## 12. 可观测性设计

### 12.1 日志记录

| 日志事件 | 阶段 | 关键字段 |
|---------|------|---------|
| research_agent_scout_start | Scout | topic |
| research_agent_survey_complete | Survey | papers, elapsed |
| research_agent_synthesize_complete | Synthesize | hypotheses, elapsed |
| research_agent_design_complete | Design | experiment, elapsed |
| research_agent_experiment_complete | Experiment | status, exit_code, elapsed |
| research_agent_analyze_complete | Analyze | hypothesis_status, confidence |
| research_agent_decide_complete | Decide | decision, iteration |
| research_gateway_routing | Gateway | phase, iteration |
| sandbox_execution_complete | Sandbox | exit_code, elapsed |

### 12.2 Langfuse追踪

每个LLM调用通过 `prompt_name` 参数自动创建Langfuse span:
- `research_scout_system`
- `research_survey_system`
- `research_synthesize_system`
- `research_design_system`
- `research_analyze_system`
- `research_decide_system`

### 12.3 研究日志 (JournalEntry)

每个阶段产出一条JournalEntry, 包含:
- phase: 哪个阶段
- summary: 一句话摘要
- details: 结构化详情 (计数, 状态等)
- created_at: 时间戳

全部日志通过 `research_journal` reducer 累加, 可通过 `/journal` API导出.

- **独立Gateway**: research_gateway vs gateway, 各自路由
