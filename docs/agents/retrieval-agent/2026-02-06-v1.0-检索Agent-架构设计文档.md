## 1. 架构概述

### 1.1 设计理念

检索Agent采用基于QDMR (Question Decomposition Meaning Representation) 的树形探索架构, 通过查询分类, QDMR分解, 树形探索和级联融合四个阶段, 实现自适应, 高质量的检索能力.

### 1.2 核心原则

1. **类型感知**: 根据查询类型选择最优检索策略
2. **自适应回溯**: 当主要策略失败时自动切换到备选策略
3. **多源融合**: 融合来自向量检索, Brave Web检索和知识图谱检索的结果
4. **可追溯性**: 所有检索结果都记录在证据图中, 支持完整追溯

### 1.3 架构层次

```
┌─────────────────────────────────────────────────────────┐
│                    RetrievalAgent                        │
│  (Pipeline Orchestrator)                                 │
└─────────────────────────────────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
        ▼                   ▼                   ▼
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ Query        │   │ Query        │   │ Tree         │
│ Classifier   │   │ Decomposer   │   │ Explorer     │
└──────────────┘   └──────────────┘   └──────────────┘
        │                   │                   │
        │                   │                   │
        ▼                   ▼                   ▼
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ Vector       │   │ KG           │   │ Cascade      │
│ Retriever    │   │ Retriever    │   │ Fuser        │
└──────────────┘   └──────────────┘   └──────────────┘
```

> 说明: Brave Web检索由`TreeExplorer`按分支策略动态调用,  
> 用于广度增强和KG空结果回退补充, 因此不单独绘制主干阶段。

## 2. 模块结构

### 2.1 模块划分

检索Agent由以下8个核心模块组成:

#### 2.1.1 RetrievalAgent (`agent.py`)

**职责**: 检索流程编排器, 协调各个模块的执行顺序.

**主要方法**:
- `_execute()`: 执行完整的检索流程

**依赖模块**:
- QueryClassifier
- QueryDecomposer
- TreeExplorer
- VectorRetriever
- BraveWebRetriever
- KGRetriever
- CascadeFuser

> **Brave链路专项说明(v1.1)**:  
> `docs/agents/retrieval-agent/2026-02-10-v1.1-Brave结果进入RAG与KG链路详解.md`

#### 2.1.2 QueryClassifier (`query_classifier.py`)

**职责**: 将用户查询分类为8种QDMR类型之一.

**主要类**:
- `QType`: QDMR类型枚举(8种类型)
- `StrategyConfig`: 策略配置数据类
- `ClassificationResult`: 分类结果数据类
- `QueryClassifier`: 分类器主类

**主要方法**:
- `classify()`: 执行查询分类

#### 2.1.3 QueryDecomposer (`query_decomposer.py`)

**职责**: 将查询分解为子查询或QDMR树形步骤.

**主要类**:
- `QueryDecomposer`: 分解器主类

**主要方法**:
- `decompose()`: 经典分解模式
- `qdmr_decompose()`: QDMR感知分解模式

#### 2.1.4 TreeExplorer (`tree_explorer.py`)

**职责**: 对QDMR步骤执行树形探索, 支持分支级回溯.

**主要类**:
- `TreeStep`: 树形步骤数据类
- `TreeExplorer`: 探索器主类

**主要方法**:
- `explore()`: 探索所有QDMR步骤
- `_execute_branch()`: 执行单个检索分支
- `_evaluate_quality()`: 评估分支质量

#### 2.1.5 VectorRetriever (`vector_retriever.py`)

**职责**: 基于PGVector的向量相似度检索.

**主要类**:
- `VectorRetriever`: 向量检索器主类

**主要方法**:
- `retrieve()`: 对子查询节点执行向量检索
- `_retrieve_for_query()`: 对单个查询执行检索

#### 2.1.6 KGRetriever (`kg_retriever.py`)

**职责**: 基于Neo4j的知识图谱多跳检索.

**主要类**:
- `KGRetriever`: KG检索器主类

**主要方法**:
- `retrieve()`: 对子查询节点执行KG检索
- `_search_and_expand()`: 搜索并扩展KG节点
- `_bfs_expand()`: BFS多跳扩展
- `_build_reasoning_chains()`: 构建推理链

#### 2.1.7 CascadeFuser (`cascade_fuser.py`)

**职责**: 多轮迭代融合来自不同检索源的结果.

**主要类**:
- `CascadeFuser`: 融合器主类

**主要方法**:
- `fuse()`: 执行级联融合
- `_llm_fuse()`: 使用LLM进行融合

#### 2.1.8 BraveWebRetriever (`web_retriever.py`)

**职责**: 调用Brave Search获取Web结果, 产出`web_result`节点并可选自动沉淀到PGVector.

**主要方法**:
- `retrieve()`: 对`sub_query/tree_step`执行Brave检索并写入证据图
- `_index_results_to_vector()`: 对TopN结果做embedding并批量upsert到`documents`

## 3. 数据流设计

### 3.1 整体数据流

```
User Query
    │
    ▼
┌─────────────────┐
│ Query           │  → ClassificationResult
│ Classifier      │
└─────────────────┘
    │
    ▼
┌─────────────────┐
│ Query           │  → List[TreeStep]
│ Decomposer      │
└─────────────────┘
    │
    ▼
┌─────────────────┐
│ Tree            │  → List[EvidenceNode]
│ Explorer        │     (breadth_nodes + depth_nodes)
└─────────────────┘
    │
    ▼
┌─────────────────┐
│ Cascade         │  → List[EvidenceNode]
│ Fuser           │     (fused_nodes)
└─────────────────┘
    │
    ▼
AgentOutput
```

### 3.2 树形探索数据流

```
TreeStep (step_idx=1)
    │
    ├─→ Primary Strategy (e.g., "rag")
    │       │
    │       ├─→ VectorRetriever
    │       │       └─→ List[EvidenceNode] (document_chunk)
    │       │
    │       └─→ Quality Evaluation
    │               │
    │               ├─→ Quality >= Threshold → Keep Results
    │               │
    │               └─→ Quality < Threshold → Backtrack
    │
    └─→ Fallback Strategy (e.g., "kg") [if backtracked]
            │
            ├─→ KGRetriever
            │       ├─→ KG Matches (kg_match)
            │       └─→ Reasoning Chains (reasoning_chain)
            │
            └─→ Quality Evaluation
                    │
                    └─→ Keep Best Branch
```

### 3.3 级联融合数据流

```
Round 1:
    breadth_nodes + depth_nodes
            │
            ├─→ LLM Fusion
            │       └─→ fused_node_1 (completeness=0.6)
            │
            └─→ Check Completeness
                    │
                    └─→ < 0.85 → Continue

Round 2:
    fused_node_1 + breadth_nodes + depth_nodes
            │
            ├─→ LLM Fusion
            │       └─→ fused_node_2 (completeness=0.8)
            │
            └─→ Check Completeness
                    │
                    └─→ < 0.85 → Continue

Round 3:
    fused_node_2 + breadth_nodes + depth_nodes
            │
            ├─→ LLM Fusion
            │       └─→ fused_node_3 (completeness=0.9)
            │
            └─→ Check Completeness
                    │
                    └─→ >= 0.85 → Stop
```

## 5. QType策略配置表

| QType | Primary Strategy | Fallback Strategy | Max Depth | Backtrack Threshold |
|-------|------------------|-------------------|-----------|---------------------|
| QSelect | rag | kg | 2 | 0.4 |
| QFilter | rag | kg | 2 | 0.4 |
| QChain | kg | rag | 3 | 0.4 |
| QComposition | both | both | 3 | 0.4 |
| QComparison | both | both | 3 | 0.4 |
| QAggregation | kg | rag | 2 | 0.4 |
| QBoolean | rag | kg | 1 | 0.4 |
| QUnion | both | both | 3 | 0.4 |

**策略说明**:
- `rag`: 仅使用向量检索
- `kg`: 仅使用知识图谱检索
- `both`: 同时使用向量检索和知识图谱检索

## 7. 证据类型设计

### 7.1 证据类型枚举

| 证据类型 | Content Type | 说明 | 来源 |
|----------|--------------|------|------|
| 查询分类 | `query_classification` | 查询分类结果 | QueryClassifier |
| 树形步骤 | `tree_step` | QDMR分解步骤 | TreeExplorer |
| 子查询 | `sub_query` | 经典分解的子查询 | QueryDecomposer |
| 文档块 | `document_chunk` | 向量检索结果 | VectorRetriever |
| KG匹配 | `kg_match` | KG直接匹配节点 | KGRetriever |
| 推理链 | `reasoning_chain` | KG BFS推理链 | KGRetriever |
| 融合证据 | `fused_evidence` | 级联融合结果 | CascadeFuser |

## 8. 错误处理设计

### 8.1 错误分类

1. **LLM调用错误**: LLM服务不可用或超时
2. **向量检索错误**: PGVector连接失败或查询错误
3. **KG检索错误**: Neo4j连接失败或查询错误
4. **解析错误**: JSON解析失败或格式错误

### 8.2 降级策略

| 错误类型 | 降级策略 |
|----------|----------|
| LLM分类失败 | 默认使用QComposition类型 |
| LLM分解失败 | 使用原始查询作为单一步骤 |
| 向量检索失败 | 跳过向量检索, 仅使用KG检索 |
| KG检索失败 | 跳过KG检索, 仅使用向量检索 |
| 融合失败 | 返回原始检索结果, 不进行融合 |

## 9. 性能优化设计

### 9.1 并发优化

- 向量检索和KG检索可以并行执行
- 不同TreeStep的检索可以并行执行(如果无依赖关系)

### 9.2 缓存策略

- 查询分类结果可以缓存(相同查询)
- 向量检索结果可以缓存(相同查询文本)

### 9.3 提前终止

- 级联融合在完整性达到0.85时提前停止
- 树形探索在质量足够时跳过备选策略

## 10. 可观测性设计

### 10.1 日志记录

所有关键操作都记录结构化日志:

- `retrieval_pipeline_start`: 检索流程开始
- `query_classified`: 查询分类完成
- `qdmr_decomposed`: QDMR分解完成
- `tree_step_start`: 树形步骤开始
- `tree_backtrack`: 树形回溯触发
- `vector_retrieval_complete`: 向量检索完成
- `kg_retrieval_complete`: KG检索完成
- `cascade_round_start`: 级联融合轮次开始
- `cascade_fusion_complete`: 级联融合完成
- `retrieval_pipeline_complete`: 检索流程完成

### 10.2 指标监控

记录以下指标:

- `q_type`: 查询类型
- `classification_confidence`: 分类置信度
- `tree_step_count`: 树形步骤数量
- `breadth_result_count`: 广度检索结果数
- `depth_chain_count`: 深度检索链数量
- `fused_count`: 融合结果数量
- `backtrack_count`: 回溯次数

### 10.3 追踪支持

- 所有LLM调用都通过Langfuse追踪
- 记录prompt名称, 输入输出, 耗时等信息
