## 1. 背景

### 1.1 项目背景

检索Agent是AI Agent系统中的核心组件, 负责从大规模知识库中检索相关信息以支持下游Agent生成高质量回答. 传统的检索方法通常采用单一策略(如向量检索或知识图谱检索), 难以应对复杂查询的多样性需求.

### 1.2 问题陈述

当前检索系统面临以下挑战:

1. **查询类型多样性**: 用户查询可能涉及简单事实查询, 多跳推理, 比较分析, 聚合统计等多种类型, 单一检索策略难以覆盖所有场景.
2. **检索质量不稳定**: 不同查询类型需要不同的检索策略, 固定策略导致某些查询的检索质量较低.
3. **缺乏自适应机制**: 当主要检索策略失败时, 系统无法自动切换到备选策略.
4. **结果融合不充分**: 来自不同检索源的结果缺乏有效的融合机制, 难以形成完整的证据链.

### 1.3 解决方案概述

基于QDMR (Question Decomposition Meaning Representation) 的树形探索检索架构, 通过以下机制解决上述问题:

- **查询分类**: 将查询分类为8种QDMR类型, 每种类型对应不同的检索策略配置.
- **QDMR分解**: 将复杂查询分解为有序的树形步骤, 每个步骤包含操作符和检索策略提示.
- **树形探索**: 对每个步骤执行主要检索策略, 如果质量低于阈值则回溯到备选策略.
- **级联融合**: 多轮迭代融合来自广度检索(RAG)和深度检索(KG)的结果, 逐步完善证据图.

## 2. 功能需求

### 2.1 查询分类功能 (FR-001)

**需求描述**: 系统应能够将用户查询分类为8种QDMR类型之一.

**功能点**:
- 支持8种QDMR类型: QSelect, QFilter, QChain, QComposition, QComparison, QAggregation, QBoolean, QUnion
- 输出分类置信度(0.0-1.0)
- 提供分类推理说明
- 为每种类型配置主要检索策略和备选检索策略

**验收标准**:
- [ ] 能够正确识别8种QDMR类型
- [ ] 分类置信度在合理范围内(>0.5)
- [ ] 分类结果包含推理说明
- [ ] 每种类型都有对应的策略配置

### 2.2 QDMR分解功能 (FR-002)

**需求描述**: 系统应能够将分类后的查询分解为有序的树形步骤.

**功能点**:
- 支持经典分解模式(平面子查询分解)
- 支持QDMR感知分解模式(树形步骤分解)
- 每个步骤包含: 步骤索引, 问题文本, 操作符, 检索策略提示, 依赖关系
- 支持步骤间的依赖关系表达(#N语法)

**验收标准**:
- [ ] 能够将查询分解为1-5个步骤
- [ ] 步骤包含完整的元数据信息
- [ ] 依赖关系正确表达
- [ ] 操作符类型符合QDMR规范

### 2.3 树形探索功能 (FR-003)

**需求描述**: 系统应能够对每个QDMR步骤执行检索, 并在质量不足时回溯到备选策略.

**功能点**:
- 对每个步骤执行主要检索策略
- 评估分支质量(平均置信度)
- 当质量低于阈值(0.4)时, 回溯到备选策略
- 保留最佳结果分支

**验收标准**:
- [ ] 每个步骤都能执行检索
- [ ] 质量评估准确(基于置信度)
- [ ] 回溯机制正常工作
- [ ] 回溯次数不超过配置限制(默认1次)

### 2.4 向量检索功能 (FR-004)

**需求描述**: 系统应支持基于PGVector的向量相似度检索.

**功能点**:
- 使用OpenAI Embeddings生成查询向量
- 在PGVector中执行相似度搜索
- 返回top_k结果(默认10)
- 结果包含相似度分数和文档元数据

**验收标准**:
- [ ] 能够生成查询向量
- [ ] 相似度搜索返回相关结果
- [ ] 结果数量不超过top_k限制
- [ ] 结果包含置信度分数

### 2.5 知识图谱检索功能 (FR-005)

**需求描述**: 系统应支持基于Neo4j的知识图谱多跳检索.

**功能点**:
- 在KG中执行全文搜索匹配实体
- 从匹配实体执行BFS多跳扩展
- 构建推理链
- 返回KG匹配节点和推理链

**验收标准**:
- [ ] 能够找到匹配的KG实体
- [ ] BFS扩展不超过最大跳数(默认3跳)
- [ ] 推理链格式正确
- [ ] 结果包含置信度分数

### 2.6 级联融合功能 (FR-006)

**需求描述**: 系统应支持多轮迭代融合来自不同检索源的结果.

**功能点**:
- 融合广度检索结果(向量检索)和深度检索结果(KG检索)
- 评估融合结果的完整性和相关性
- 识别信息缺口
- 多轮迭代(最多3轮)逐步完善证据

**验收标准**:
- [ ] 能够融合不同来源的结果
- [ ] 融合结果包含完整性和相关性评分
- [ ] 能够识别信息缺口
- [ ] 当完整性达到阈值(0.85)时提前停止

## 3. 非功能需求

### 3.1 性能需求 (NFR-001)

- **响应时间**: 单次检索请求应在10秒内完成(不含LLM调用时间)
- **并发处理**: 支持至少10个并发检索请求
- **资源占用**: 内存占用不超过2GB

### 3.2 可靠性需求 (NFR-002)

- **错误处理**: 所有检索失败应有降级策略
- **超时控制**: LLM调用超时时间不超过30秒
- **重试机制**: 网络错误自动重试最多3次

### 3.3 可扩展性需求 (NFR-003)

- **策略扩展**: 支持添加新的检索策略
- **类型扩展**: 支持添加新的QDMR类型
- **配置灵活**: 所有关键参数可通过环境变量配置

### 3.4 可观测性需求 (NFR-004)

- **日志记录**: 所有关键操作都有结构化日志
- **指标监控**: 记录检索质量, 回溯次数, 融合轮数等指标
- **追踪支持**: 集成Langfuse进行LLM调用追踪

## 4. 约束条件

### 4.1 技术约束

- **LLM服务**: 必须使用配置的LLM服务(OpenAI兼容API)
- **向量存储**: 必须使用PGVector作为向量存储
- **知识图谱**: 必须使用Neo4j作为知识图谱存储
- **Python版本**: 必须使用Python 3.10+

### 4.2 数据约束

- **查询长度**: 用户查询不超过500字符
- **步骤数量**: QDMR分解步骤不超过5个
- **检索结果**: 单次检索返回结果不超过100个节点

### 4.3 业务约束

- **成本控制**: LLM调用次数应尽可能少
- **质量保证**: 检索结果必须包含置信度分数
- **可追溯性**: 所有检索结果必须能够追溯到原始查询

## 5. 术语表

| 术语 | 英文 | 说明 |
|------|------|------|
| QDMR | Question Decomposition Meaning Representation | 问题分解意义表示, 一种查询分类和分解框架 |
| QType | Query Type | 查询类型, 8种QDMR分类之一 |
| TreeStep | Tree Step | 树形步骤, QDMR分解后的单个检索步骤 |
| 回溯 | Backtrack | 当主要策略质量不足时切换到备选策略 |
| 级联融合 | Cascade Fusion | 多轮迭代融合不同检索源的结果 |
| 广度检索 | Breadth Retrieval | 基于向量相似度的文档检索 |
| 深度检索 | Depth Retrieval | 基于知识图谱的多跳推理检索 |
| 证据图 | Evidence Graph | 存储检索结果和推理关系的图结构 |
| 置信度 | Confidence | 检索结果的可信度分数(0.0-1.0) |
| 操作符 | Operator | QDMR步骤的操作类型(select, filter, project等) |
