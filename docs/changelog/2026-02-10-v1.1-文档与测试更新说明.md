# 昊中多Agent系统 — 文档与测试更新说明

**版本**: v1.1  
**日期**: 2026-02-10  
**状态**: 已落地

---

## 1. 更新目标

本次更新面向近期线上与联调反馈, 聚焦三类问题:

1. 检索链路稳定性: Brave 自动入库触发 PGVector `ivfflat` 维度限制报错。
2. 多阶段状态机一致性: 测试仍使用旧阶段命名(`retrieval/generation/evaluation`)。
3. 前端可观测性可靠性: 中间产物 metadata 类型不稳定导致前端解析异常。
4. 检索链路可理解性: 对“Brave结果如何进入RAG/KG”的解释需要更细化。

---

## 2. 代码行为基线(已实现)

### 2.1 向量库索引维度保护

- 文件: `app/infra/vector_store/pgvector.py`
- 行为:
  - 当 `EMBEDDING_DIMENSION <= 2000` 时创建 `ivfflat` 索引。
  - 当 `EMBEDDING_DIMENSION > 2000` 时跳过索引创建并记录告警, 仍允许建表与入库。
- 目的: 避免 `ProgramLimitExceeded: column cannot have more than 2000 dimensions for ivfflat index` 直接导致检索链路失败。

### 2.2 证据不足提示动态化

- 文件: `app/orchestration/nodes.py`
- 行为:
  - `assemble_output()` 在“全部生成段落无有效填槽”时, 基于 query 关键词生成动态提示。
  - 中英文 query 分别返回中文/英文提示文本。
- 目的: 避免硬编码主题(如东北经济)污染无关查询结果。

### 2.3 Agent 指标模型兼容

- 文件: `app/core/types/agent_io.py`
- 行为: `AgentOutput.metrics` 使用 `Dict[str, Any]`。
- 目的: 支持 `q_type` 等字符串指标, 保证后端与前端指标展示一致。

### 2.4 Brave进入RAG/KG链路解释补充

- 新增文档:  
  `docs/agents/retrieval-agent/2026-02-10-v1.1-Brave结果进入RAG与KG链路详解.md`
- 关键结论:
  - Brave同轮进入证据图为`web_result`, 作为广度证据参加Cascade融合。
  - Brave可跨轮沉淀到PGVector, 后续以`document_chunk`形态被RAG召回。
  - Brave当前不会直接写入Neo4j KG。

### 2.5 关键词相关性门控鲁棒性修复

- 文件:
  - `app/agents/generation/proposal_decomposer.py`
  - `app/agents/generation/content_generator.py`
  - `app/orchestration/nodes.py`
- 行为:
  - 中文比较句关键词提取从“整句匹配”改为“实体级切分”。
  - 关键词过滤后若候选为空, 自动回退到过滤前候选, 避免误杀全部证据。
- 目的:
  - 修复“检索有证据但生成阶段误判证据不足”的问题。

### 2.6 关键词提取能力升级(在线词典+可选LLM)

- 文件:
  - `app/core/nlp/query_keyword_extractor.py`
  - `app/agents/generation/proposal_decomposer.py`
  - `app/agents/generation/content_generator.py`
  - `app/orchestration/nodes.py`
- 行为:
  - 引入在线停用词词典(`stopwordsiso`)和中文分词(`jieba`)替代硬编码停用词表。
  - 三处关键词提取逻辑统一复用同一提取器, 保持行为一致。
  - 新增可选开关, 支持使用LLM执行 query 关键词拆分(默认关闭)。
- 目的:
  - 降低手工维护 stopwords 成本。
  - 提升复杂query(比较/对抗/长句)的拆分质量。

### 2.7 PG混合检索(Hybrid Retrieval)支持

- 文件:
  - `app/infra/vector_store/pgvector.py`
  - `app/agents/retrieval/vector_retriever.py`
  - `app/core/config.py`
- 行为:
  - 新增 `sparse_search()`(关键词ILIKE匹配)。
  - 新增 `hybrid_search()`(Dense + Sparse, 加权RRF融合)。
  - `VectorRetriever` 支持通过配置选择 `dense/hybrid` 模式。
  - `ensure_table()` 增加 `pg_trgm` 扩展与 `gin_trgm_ops` 索引。
- 目的:
  - 让PG检索同时兼顾语义相似与关键词精确命中, 提升多类型查询召回稳定性。

### 2.8 API表现层线程池并发

- 文件:
  - `app/presentation/api/v1/agent.py`
  - `app/core/config.py`
- 行为:
  - `chat/status/review` 的响应组装逻辑通过 `ThreadPoolExecutor` 并发执行。
  - 表现层线程池仅用于中间产物分组、metrics汇总、状态序列化等展示逻辑。
  - Agent执行链路保持串行编排, 不在业务Agent层做并发改动。
- 目的:
  - 在高并发请求下提升API表现层吞吐, 避免阻塞主事件循环。

## 5. 运行与验收

### 5.1 运行命令

```bash
python -m pytest tests/unit tests/smoke -q
```

### 5.2 验收标准

1. UT 与 smoke 全部通过。
2. 不依赖真实 Neo4j/PGVector 即可执行测试(除集成环境专项测试)。
3. 关键回归点具备直接断言:
   - 高维 embedding 不再触发 `ivfflat` 维度异常。
   - 动态证据不足提示不再出现硬编码主题。
   - `web_result` metadata 保持前端可解析的原生结构。

## 6. 已知边界

1. 本批测试主要覆盖“行为回归与稳定性”, 不替代全链路性能压测。
2. `python-jose` 在部分本地环境缺失时, 冒烟测试将通过测试层隔离来避免阻塞 API 结构验证。
