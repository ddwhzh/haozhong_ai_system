# 2026-02-10 v1.3 Neo4j连接稳定性修复

## 1. 变更目标

- 修复 `Neo4j` 在容器启动早期出现 `incomplete handshake response` 时导致的链路不稳定问题。
- 降低 `Neo4j` 不可用场景下对问答链路的级联影响, 避免请求长时间阻塞后被网关返回 5xx。
- 修复评测脚本在异常分支下的延迟统计错误, 避免产出无效准确率报告。

## 2. 根因与证据

1) 健康检查口径不一致  
- 现状: `docker-compose.yml` 中 `neo4j` 健康检查只探活 HTTP `7474`。  
- 问题: 应用实际依赖 Bolt `7687`; HTTP ready 不代表 Bolt 握手可用。  

2) Neo4j客户端连接鲁棒性不足  
- 现状: `app/infra/neo4j/client.py` 在连接失败时缺少标准重试与冷却控制。  
- 风险: 服务不可用期间会产生重复连接尝试, 放大超时与错误传播风险。  

3) 评测脚本异常分支统计缺陷  
- 现状: `test_script/2026-02-10-dataset-accuracy-eval.py` 异常路径把 `time.time()` 绝对时间写入 `latency_seconds`。  
- 结果: 报告平均延迟被污染, 准确率解释失真。  

## 3. 本次实现的事实变更

1) Neo4j容器健康检查改为 Bolt 可用性检查  
- 文件: `docker-compose.yml`  
- 变化: `neo4j` healthcheck 从 HTTP 探活改为 `cypher-shell` 执行 `RETURN 1`。

2) Neo4j客户端连接能力增强  
- 文件: `app/infra/neo4j/client.py`  
- 变化: 增加指数退避重试、失败后连接冷却窗口、连接失败后的驱动清理与显式日志。  
- 变化: 保持接口不变, 对调用方透明。

3) 评测脚本修正异常延迟统计  
- 文件: `test_script/2026-02-10-dataset-accuracy-eval.py`  
- 变化: 异常分支改为记录单条样本耗时, 不再写入 Unix 时间戳。

## 4. 与代码实现的映射

- `docker-compose.yml`: `neo4j.healthcheck` 逻辑与启动依赖时序。  
- `app/infra/neo4j/client.py`: `connect/health_check` 的连接管理与重试。  
- `test_script/2026-02-10-dataset-accuracy-eval.py`: `main()` 循环中失败样本统计。  

## 5. 假设与边界

- 假设 A: 运行环境允许在 `neo4j` 容器中执行 `cypher-shell`。  
- 假设 B: 当前系统允许在 `Neo4j` 不可用时降级继续执行其他检索路径。  
- 边界: 本次不改变业务问答策略, 仅修复连接稳定性与评测统计。

## 6. 未实现或延期项

- 未新增端到端容器编排集成测试; 本次以代码级与脚本级最小验证为主。  
- 未引入新的监控告警规则, 仅保留现有日志可观测能力。
