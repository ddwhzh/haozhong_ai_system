## 1. 接口总览表

| 方法 | 路径 | 功能 | 认证 | 说明 |
|------|------|------|------|------|
| GET | `/` | 系统信息 | 否 | 返回系统名称, 版本, 架构信息, Agent列表 |
| GET | `/health` | 健康检查 | 否 | 检查API, 数据库, Neo4j组件状态 |
| POST | `/api/v1/agent/chat` | 同步对话 | 否 | 完整执行多Agent管道, 返回最终结果 |

## 2. 详细接口说明

### 2.1 POST /api/v1/agent/chat — 同步对话

完整执行多Agent管道(检索 -> 生成 -> 评估 -> 输出), 返回最终结果.

**请求体** (`ChatRequest`):

```json
{
    "query": "string (必填, 用户查询, 最小长度1)",
    "session_id": "string (可选, 会话ID, 不填自动生成UUID)",
    "user_id": "string (可选, 用户标识, 默认anonymous)",
    "metadata": {
        "key": "value (可选, 任意键值对, 默认空对象)"
    },
    "max_iterations": 10
}
```

**字段验证规则**:
- `query`: 必填, 字符串类型, 最小长度1字符
- `session_id`: 可选, 字符串类型, 如不提供则自动生成UUID
- `user_id`: 可选, 字符串类型, 默认值为 `"anonymous"`
- `metadata`: 可选, 对象类型, 默认值为空对象 `{}`
- `max_iterations`: 可选, 整数类型, 范围1-50, 默认值为10

### 2.2 POST /api/v1/agent/chat/stream — 流式对话(SSE)

以Server-Sent Events格式流式返回管道执行过程.

**请求体**: 与 `/api/v1/agent/chat` 相同 (`ChatRequest`)

**响应**: `text/event-stream` 媒体类型

**事件类型**:

1. **phase_start**: 阶段开始
```json
data: {"event": "phase_start", "name": "retrieval_agent"}

```

2. **phase_end**: 阶段结束
```json
data: {"event": "phase_end", "name": "retrieval_agent"}

```

3. **token**: 生成的内容片段(流式输出)
```json
data: {"event": "token", "content": "部分"}

data: {"event": "token", "content": "生成"}

data: {"event": "token", "content": "内容"}

```

4. **done**: 执行完成
```json
data: {"event": "done"}

```

5. **error**: 执行错误
```json
data: {"event": "error", "message": "错误信息"}

```

**事件字段说明**:
- `event` (string, 必填): 事件类型, 可能值: `phase_start`, `phase_end`, `token`, `done`, `error`
- `name` (string, 可选): 阶段名称(仅用于 `phase_start` 和 `phase_end`)
- `content` (string, 可选): 内容片段(仅用于 `token`)
- `message` (string, 可选): 错误消息(仅用于 `error`)

**使用示例** (JavaScript):

```javascript
const eventSource = new EventSource('/api/v1/agent/chat/stream', {
    method: 'POST',
    body: JSON.stringify({ query: '用户查询' })
});

eventSource.onmessage = (event) => {
    const data = JSON.parse(event.data);
    if (data.event === 'token') {
        // 追加内容片段
        outputElement.textContent += data.content;
    } else if (data.event === 'done') {
        eventSource.close();
    } else if (data.event === 'error') {
        console.error(data.message);
        eventSource.close();
    }
};
```

### 2.3 POST /api/v1/agent/review — HITL人工审核

当管道在HITL节点暂停时, 提交人工审核决策.

**请求体** (`HumanReviewRequest`):

```json
{
    "session_id": "string (必填, 暂停管道的会话ID)",
    "action": "approve | reject | edit (必填, 必须匹配正则: ^(approve|reject|edit)$)",
    "feedback": "string (可选, 人工反馈文本, action=reject时建议填写, 默认空字符串)",
    "edits": {
        "key": "value (可选, 直接修改证据图, 仅用于action=edit)"
    }
}
```

**字段验证规则**:
- `session_id`: 必填, 字符串类型
- `action`: 必填, 字符串类型, 必须为 `approve`, `reject`, 或 `edit` 之一
- `feedback`: 可选, 字符串类型, 默认值为空字符串 `""`
- `edits`: 可选, 对象类型, 默认值为 `null`, 仅在 `action=edit` 时使用

**Action说明**:

| action | 效果 | 说明 |
|--------|------|------|
| approve | 确认通过, 管道继续到输出组装 | 无需额外参数, 直接继续执行 |
| reject | 打回重新生成, feedback作为额外上下文 | 建议填写 `feedback` 字段, 触发重新生成 |
| edit | 直接修改后继续 | 使用 `edits` 字段修改证据图, 然后继续执行 |

**响应体**: 与 `/api/v1/agent/chat` 相同 (`ChatResponse`)

**错误响应**:

- **400 Bad Request**: 请求体验证失败
```json
{
    "detail": [
        {
            "loc": ["body", "action"],
            "msg": "string does not match regex '^(approve|reject|edit)$'",
            "type": "value_error.str.regex"
        }
    ]
}
```

- **500 Internal Server Error**: 人工审核处理失败
```json
{
    "detail": "<error message>"
}
```

                "sub_query_count": 3,
                "breadth_result_count": 10,

**响应字段说明**:

### 2.6 GET /health — 健康检查

检查API, 数据库, Neo4j等组件的健康状态.

**响应体**:

- **200 OK**: 所有组件健康
```json
{
    "status": "healthy",
    "version": "0.1.0",
    "environment": "development",
    "components": {
        "api": "healthy",
        "database": "healthy",
        "neo4j": "healthy"
    },
    "timestamp": "2026-02-06T12:00:00.000000"
}
```

- **503 Service Unavailable**: 至少一个组件不健康
```json
{
    "status": "degraded",
    "version": "0.1.0",
    "environment": "development",
    "components": {
        "api": "healthy",
        "database": "healthy",
        "neo4j": "unhealthy"
    },
    "timestamp": "2026-02-06T12:00:00.000000"
}
```

**响应字段说明**:
- `status` (string): 整体状态, `healthy` 表示所有组件健康, `degraded` 表示至少一个组件不健康
- `version` (string): 版本号
- `environment` (string): 运行环境
- `components` (object): 各组件状态
  - `api` (string): API服务状态, 固定为 `"healthy"`
  - `database` (string): 数据库状态, `healthy` 或 `unhealthy`
  - `neo4j` (string): Neo4j状态, `healthy` 或 `unhealthy`
- `timestamp` (string): 检查时间戳, ISO 8601格式

**状态码说明**:
- `200`: 所有组件健康
- `503`: 至少一个组件不健康

## 3. 内部Agent I/O接口

### 3.1 AgentInput (Worker节点输入)

Worker节点接收的标准输入信封, 由编排层从全局 `PipelineState` 构造.

```python
class AgentInput(BaseModel):
    query: str                          # 当前用户查询或子任务描述
    evidence_graph: EvidenceGraph        # 共享证据图(只读快照)
    context: Dict[str, Any]             # Agent特定上下文/参数(由Gateway提供)
    conversation_history: List[Dict[str, str]]  # 最近的对话消息(用于上下文)
    max_iterations: int                  # 该Agent允许的最大迭代次数(默认3)
```

**字段说明**:
- `query` (string, 必填): 当前用户查询或子任务描述
- `evidence_graph` (EvidenceGraph, 必填): 共享证据图, Worker节点获得只读快照, 不能直接修改
- `context` (dict, 可选): Agent特定上下文或参数, 由Gateway节点设置, 默认空字典
- `conversation_history` (array, 可选): 最近的对话消息列表, 格式为 `[{"role": "user", "content": "..."}, ...]`, 默认空列表
- `max_iterations` (integer, 可选): 该Agent允许的最大迭代次数, 默认值为3

### 3.2 AgentOutput (Worker节点输出)

Worker节点返回的标准输出信封, 编排层将新证据节点和信念更新合并到全局 `PipelineState`.

```python
class AgentOutput(BaseModel):
    agent_name: str                     # 产生此输出的Agent名称
    status: AgentStatus                 # 执行状态枚举: success | partial | needs_more_info | error
    new_nodes: List[EvidenceNode]        # 要添加到图的新证据节点
    belief_updates: List[BeliefUpdate]   # 对现有信念的修改提案
    summary: str                         # 人类可读的执行摘要
    metrics: Dict[str, float]            # Agent特定指标(延迟, token计数等)
    error_message: Optional[str]         # 错误信息(仅在status=error时使用)
    created_at: datetime                 # 创建时间戳(UTC)
```

**字段说明**:
- `agent_name` (string, 必填): 产生此输出的Agent名称, 例如 `"retrieval_agent"`
- `status` (AgentStatus, 必填): 执行状态枚举
  - `success`: 成功完成
  - `partial`: 部分完成, 有结果但存在警告
  - `needs_more_info`: 需要更多信息才能继续
  - `error`: 执行失败
- `new_nodes` (array[EvidenceNode], 可选): 要添加到证据图的新节点列表, 默认空列表
- `belief_updates` (array[BeliefUpdate], 可选): 对现有节点信念的修改提案列表, 默认空列表
- `summary` (string, 可选): 人类可读的执行摘要, 默认空字符串
- `metrics` (dict, 可选): Agent特定指标字典, 键为字符串, 值为浮点数, 默认空字典
- `error_message` (string, 可选): 错误信息, 仅在 `status=error` 时使用, 默认 `None`
- `created_at` (datetime, 必填): 创建时间戳, UTC时区, 自动生成

### 3.3 PipelineState (全局状态)

流经LangGraph编排图的全局状态, 所有Worker节点通过 `AgentInput`/`AgentOutput` 读写此状态.

```python
class PipelineState(BaseModel):
    messages: list                       # LangChain消息列表(自动合并)
    query: str                          # 用户查询
    evidence_graph: EvidenceGraph        # 证据图
    agent_outputs: List[AgentOutput]     # Agent执行日志(有序列表)
    current_phase: str                   # 当前管道阶段(PipelinePhase枚举值)
    next_agent: str | None              # 下一个Agent(仅Gateway设置)
    iteration_count: int                 # 迭代计数器
    max_iterations: int                  # 最大迭代数(默认10)
    rollback_count: int                  # 回滚计数器
    max_rollbacks: int                  # 最大回滚次数(默认1)
    context_manifest: Dict[str, Any]    # Freeze阶段快照: 证据摘要/缺口/检索统计
    plan_dag: List[Dict[str, Any]]      # Plan阶段生成的slot-filling proposal列表
    validation_feedback: str             # Validate失败时的反馈(用于Rollback)
    final_output: str                    # 最终输出文本
    metadata: Dict[str, Any]            # 元数据(user_id, session_id, trace_id等)
```

**字段说明**:
- `messages` (list, 可选): LangChain格式的消息列表, 使用 `add_messages` 自动合并, 默认空列表
- `query` (string, 可选): 当前用户查询, 默认空字符串
- `evidence_graph` (EvidenceGraph, 可选): 共享证据图, 所有Agent贡献到此图, 默认新建空图
- `agent_outputs` (array[AgentOutput], 可选): Agent执行结果的有序日志, 使用 `_merge_agent_outputs` 自动追加, 默认空列表
- `current_phase` (string, 可选): 当前管道阶段, 使用 `PipelinePhase` 枚举值, 默认 `"explore"`
- `next_agent` (string, 可选): 下一个要路由到的Agent名称, 仅由Gateway节点设置, 默认 `None`
- `iteration_count` (integer, 可选): 全局迭代计数器, 默认0
- `max_iterations` (integer, 可选): 硬性迭代上限, 默认10
- `rollback_count` (integer, 可选): 回滚计数器, 默认0
- `max_rollbacks` (integer, 可选): 硬性回滚上限, 默认1
- `context_manifest` (dict, 可选): Freeze阶段快照, 包含证据摘要, 信息缺口, 检索统计等, 默认空字典
- `plan_dag` (array, 可选): Plan阶段生成的slot-filling proposal有序列表, 默认空列表
- `validation_feedback` (string, 可选): Validate阶段失败时的反馈信息, 用于Rollback阶段, 默认空字符串
- `final_output` (string, 可选): 最终生成的回答文本, 默认空字符串
- `metadata` (dict, 可选): 任意元数据, 通常包含 `user_id`, `session_id`, `trace_id` 等, 默认空字典

**PipelinePhase枚举值**:
- `explore`: 检索阶段, RAG + KG并行搜索, Cascade融合
- `freeze`: 快照阶段, 写入 `context_manifest` + 证据快照
- `plan`: 规划阶段, Proposal分解, 写入todo DAG
- `execute`: 执行阶段, 按proposal生成内容, 有界步骤
- `validate`: 验证阶段, 评估: 评分 + 匈牙利匹配
- `done`: 完成阶段, 组装输出
- `rollback`: 回滚阶段, 验证失败, 扩展/修复manifest, 重试
- `human_review`: 人工审核阶段, HITL检查点

### 4.2 LLM服务调用

LLM服务支持通过 `prompt_name` 参数记录使用的Prompt, 用于追踪和日志.

**函数签名**:
```python
async def call(
    messages: List[BaseMessage],
    model_name: Optional[str] = None,
    prompt_name: Optional[str] = None,
    **kwargs,
) -> BaseMessage
```

**参数说明**:
- `messages` (array[BaseMessage], 必填): LangChain消息列表
- `model_name` (string, 可选): 覆盖使用的模型名称
- `prompt_name` (string, 可选): 使用的Prompt文件名(用于追踪/日志)
- `**kwargs`: 额外的模型参数

**返回值**:
- `BaseMessage`: LLM响应消息

**使用示例**:
```python
from app.infra.llm import llm_service
from langchain_core.messages import SystemMessage, HumanMessage
from app.prompts import load_prompt

messages = [
    SystemMessage(content=load_prompt("query_decompose_system", max_sub_queries=5)),
    HumanMessage(content="Decompose this query:\n用户查询"),
]

response = await llm_service.call(
    messages,
    prompt_name="query_decompose_system"  # 记录使用的Prompt
)
```

**说明**: `prompt_name` 参数不会影响LLM调用, 仅用于日志记录和Langfuse追踪.

## 5. 证据图节点类型清单

证据图中的节点使用 `content_type` 字段标识节点类型. 以下是所有12种节点类型及其说明:

| content_type | 来源Agent | 阶段 | 典型metadata | 说明 |
|--------------|-----------|------|--------------|------|
| `query_classification` | retrieval_agent | Classify | `{"q_type": "QChain", "confidence": 0.85, "primary_strategy": "kg", "fallback_strategy": "rag"}` | QDMR查询分类结果 |
| `tree_step` | retrieval_agent | Explore | `{"step_idx": 1, "operator": "select", "retrieval_strategy": "kg", "depends_on": []}` | QDMR分解树步骤 |
| `query` | retrieval_agent | Explore | `{}` | 根查询节点(经典分解模式) |
| `sub_query` | retrieval_agent | Explore | `{"aspect": "定义"}` | 查询分解后的子查询(经典分解模式) |
| `document_chunk` | retrieval_agent | Explore | `{"source": "doc_id", "chunk_index": 0, "similarity_score": 0.87}` | RAG向量检索结果 |
| `kg_match` | retrieval_agent | Explore | `{"entity_id": "entity_123", "entity_type": "Concept"}` | KG知识图谱实体匹配 |
| `reasoning_chain` | retrieval_agent | Explore | `{"chain_index": 0, "chain_length": 3, "seed_entities": [...], "depth": 2}` | KG推理链(BFS多跳结果) |
| `fused_evidence` | retrieval_agent | Explore | `{"fusion_round": 2, "source_count": 3}` | Cascade融合结果 |
| `proposal` | generation_agent | Plan | `{"aspect": "定义", "slot_count": 3}` | Proposal槽位定义 |
| `generated_content` | generation_agent | Execute | `{"aspect": "定义", "filled_slots": {...}}` | 证据图填空结果 |
| `evaluation_result` | evaluation_agent | Validate | `{"faithfulness_rate": 0.9, "overall_score": 0.82, "sections_evaluated": 3}` | 匈牙利匹配评估结果 |
| `prompt_optimization` | evaluation_agent | Validate | `{"target": "generation_agent", "expected_improvement": 0.3}` | Prompt优化建议 |

**节点类型分组**:

1. **Explore阶段** (检索Agent):
   - `query`: 根查询节点
   - `sub_query`: 查询分解
   - `document_chunk`: RAG向量检索
   - `kg_match`: KG实体匹配
   - `reasoning_chain`: KG推理链
   - `fused_evidence`: Cascade融合

2. **Plan/Execute阶段** (生成Agent):
   - `proposal`: Proposal槽位定义
   - `generated_content`: 生成的段落内容

3. **Validate阶段** (评估Agent):
   - `evaluation_result`: 评估结果
   - `prompt_optimization`: Prompt优化建议

**IntermediateStep标签映射**:

在 `intermediate_steps` 响应中, 节点按以下标签分组显示:

- `"1. Explore: 查询分解 (子查询)"` → `sub_query`
- `"2. Explore: RAG向量检索结果"` → `document_chunk`
- `"3. Explore: KG知识图谱匹配"` → `kg_match`
- `"4. Explore: KG推理链"` → `reasoning_chain`
- `"5. Explore: Cascade融合结果"` → `fused_evidence`
- `"6. Plan: Proposal槽位定义"` → `proposal`
- `"7. Execute: 证据图填空结果"` → `generated_content`
- `"8. Validate: 匈牙利匹配评估"` → `evaluation_result`
- `"9. Validate: Prompt优化建议"` → `prompt_optimization`

注意: `query` 类型节点通常不显示在 `intermediate_steps` 中, 因为它是根节点.

## 6. 错误处理

### 6.1 HTTP状态码

| 状态码 | 说明 | 常见场景 |
|--------|------|----------|
| 200 | 成功 | 正常响应 |
| 400 | 请求错误 | 请求体验证失败 |
| 404 | 未找到 | 会话不存在 |
| 422 | 验证错误 | 字段级验证失败(由FastAPI自动生成) |
| 429 | 请求过多 | 速率限制触发(由slowapi提供) |
| 500 | 服务器错误 | 管道执行失败, 内部错误 |
| 503 | 服务不可用 | 健康检查发现组件不健康 |

### 6.2 错误响应格式

**验证错误** (422):
```json
{
    "detail": [
        {
            "loc": ["body", "field_name"],
            "msg": "error message",
            "type": "error_type"
        }
    ]
}
```

**通用错误** (400, 404, 500, 503):
```json
{
    "detail": "error message"
}
```
