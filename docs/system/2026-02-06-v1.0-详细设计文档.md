### 1.2 QueryClassifier 详细算法设计 (新增)

**职责**: 基于QDMR将查询分为8个类别, 输出分类结果和策略配置.

**完整算法流程**:

```
输入: query (str), evidence_graph (EvidenceGraph)
输出: (ClassificationResult, EvidenceNode)

步骤1: LLM分类
  1.1 加载System Prompt:
      - 从 app/prompts/query_classify_system.md 加载
      - 传入 max_depth 参数
  1.2 构建消息:
      SystemMessage: load_prompt("query_classify_system", max_depth=self.max_depth)
      HumanMessage: "Classify this query:\n{query}"
  1.3 调用LLM:
      response = await llm_service.call(messages, prompt_name="query_classify_system")
  1.4 JSON解析:
      - 处理markdown代码块
      - 提取 q_type, confidence, reasoning, decomposition_hint
  1.5 枚举映射:
      - 将字符串映射到 QType 枚举 (QSelect, QFilter, ...)
      - 未知类型 fallback 到 QSelect
  1.6 策略配置:
      - 通过 StrategyConfig.for_type(q_type, backtrack_threshold) 获取
      - 返回: primary_strategy, fallback_strategy, max_decomposition_depth, backtrack_threshold

步骤2: 创建证据节点
  - content_type = "query_classification"
  - content = JSON({q_type, confidence, reasoning, primary_strategy, fallback_strategy})
  - metadata = {q_type, confidence, reasoning, primary_strategy, fallback_strategy, max_depth}
  - intent = IntentType.DECOMPOSE_QUERY
  - tags = ["query_classification", q_type.lower()]

步骤3: 异常处理 (Fallback)
  如果LLM调用或解析失败:
    - 默认分类为 QComposition (最通用类型)
    - confidence = 0.5
    - 使用 QComposition 的策略配置
```

**QType 枚举**:

```python
class QType(str, Enum):
    Q_SELECT = "QSelect"
    Q_FILTER = "QFilter"
    Q_CHAIN = "QChain"
    Q_COMPOSITION = "QComposition"
    Q_COMPARISON = "QComparison"
    Q_AGGREGATION = "QAggregation"
    Q_BOOLEAN = "QBoolean"
    Q_UNION = "QUnion"
```

**StrategyConfig 默认映射**:

| QType | primary | fallback | max_depth | backtrack_threshold |
|-------|---------|----------|-----------|-------------------|
| QSelect | rag | kg | 2 | 0.4 |
| QFilter | rag | kg | 2 | 0.4 |
| QChain | kg | rag | 3 | 0.4 |
| QComposition | both | both | 3 | 0.4 |
| QComparison | both | both | 3 | 0.4 |
| QAggregation | kg | rag | 2 | 0.4 |
| QBoolean | rag | kg | 1 | 0.4 |
| QUnion | both | both | 3 | 0.4 |

### 1.3 TreeExplorer 详细算法设计 (新增)

**职责**: 逐步骤执行检索, 主策略质量不足时回退到备选策略.

**完整算法流程**:

```
输入: steps (List[TreeStep]), classification (ClassificationResult),
      evidence_graph (EvidenceGraph), parent_node (EvidenceNode)
输出: List[EvidenceNode] (所有探索得到的节点)

对每个 step in steps:
  步骤1: 创建步骤节点
    - content_type = "tree_step"
    - content = step.question
    - metadata = {step_idx, operator, retrieval_strategy, depends_on, q_type}
    - parent = classification证据节点
    - relation = DECOMPOSES_TO

  步骤2: 确定策略
    - primary = resolve_strategy(step.retrieval_strategy, classification.strategy.primary_strategy)
    - fallback = resolve_strategy(step.retrieval_strategy, classification.strategy.fallback_strategy)

  步骤3: 执行主策略分支
    - if strategy in ("rag", "both"):
        rag_nodes = vector_retriever.retrieve([step_node], evidence_graph)
    - if strategy in ("kg", "both"):
        kg_nodes = kg_retriever.retrieve([step_node], evidence_graph)
    - branch_nodes = rag_nodes + kg_nodes

  步骤4: 评估分支质量
    - quality = mean(n.belief.confidence for n in branch_nodes)

  步骤5: 回退判断
    - if quality < backtrack_threshold AND fallback != primary:
        - 执行备选策略分支 (同步骤3逻辑)
        - fallback_quality = mean(confidence)
        - 如果 fallback_quality > quality:
            - 替换为备选结果
        - 否则:
            - 合并两者结果

  步骤6: 记录结果
    - step.results = branch_nodes
    - step.quality = quality
    - step.backtracked = True/False
```

**策略解析逻辑** (`_resolve_strategy`):

```
如果 step_strategy 是 "rag" 或 "kg" -> 直接使用
如果 step_strategy 是 "both" 或未知 -> 使用 type_strategy (来自分类)
```

**质量评估** (`_evaluate_quality`):

```
如果结果节点为空 -> 返回 0.0
否则 -> 返回 sum(confidence) / count(nodes)
```

### 1.4 QueryDecomposer 详细算法设计

**职责**: 支持经典分解(旧) + QDMR类型感知分解(新).

**完整算法流程**:

```
输入: query (str), evidence_graph (EvidenceGraph)
输出: List[EvidenceNode] (包含根查询节点 + 所有子查询节点)

步骤1: 创建根查询节点
  - content_type = "query"
  - content = query (原始查询文本)
  - confidence = 1.0 (根查询置信度最高)
  - intent = IntentType.RETRIEVE
  - tags = ["query", "root"]
  - 将root_node添加到evidence_graph

步骤2: LLM分解查询
  2.1 加载System Prompt:
      - 从 app/prompts/query_decompose_system.md 加载
      - Prompt包含规则: 每个子查询独立可搜索, 避免冗余, 保留原意图
      - 通过format()传入max_sub_queries参数 (默认5, 可配置)
  
  2.2 构建消息:
      SystemMessage: load_prompt("query_decompose_system", max_sub_queries=self.max_sub_queries)
      HumanMessage: "Decompose this query:\n{query}"
  
  2.3 调用LLM:
      response = await llm_service.call(messages, prompt_name="query_decompose_system")
      content = response.content.strip()
  
  2.4 JSON解析 (带容错):
      - 如果content包含```代码块标记, 提取代码块内容
      - 如果代码块以"json"开头, 跳过前4个字符
      - 使用json.loads()解析
      - 验证是否为list类型
      - 截取前max_sub_queries个元素
  
  2.5 异常处理 (Fallback):
      如果LLM调用失败或解析失败:
        - 记录错误日志: logger.error("query_decomposition_failed", error=str(e))
        - 返回单元素列表: [{"query": query, "aspect": "original"}]

步骤3: 创建子查询节点
  遍历sub_queries列表, 对每个sq:
    3.1 提取字段:
        sq_text = sq.get("query", query)  # 默认使用原始查询
        aspect = sq.get("aspect", f"aspect_{i}")  # 默认生成aspect名称
    
    3.2 创建EvidenceNode:
        - content_type = "sub_query"
        - content = sq_text
        - source = "query_decomposer"
        - metadata = {"aspect": aspect, "index": i}
        - confidence = 0.9 (子查询置信度略低于根查询)
        - intent = IntentType.DECOMPOSE_QUERY
        - intent.parameters = {"aspect": aspect, "parent_query": query}
        - tags = ["sub_query", aspect]
        - parent_node_ids = [root_node.node_id]
        - relation = EdgeRelation.DECOMPOSES_TO (建立分解关系边)
    
    3.3 添加到graph并收集到sub_query_nodes列表

步骤4: 返回结果
  返回 [root_node] + sub_query_nodes
```

**关键配置项**:
- `RETRIEVAL_MAX_SUB_QUERIES`: 最大子查询数量 (默认5)
- Prompt文件路径: `app/prompts/query_decompose_system.md`

**降级策略**: LLM调用失败时, 将原始查询作为唯一子查询继续, 确保管道不会中断.

### 1.3 VectorRetriever 详细算法设计

**职责**: 对每个子查询执行embedding相似度搜索, 返回top_k文档片段.

**完整算法流程**:

```
输入: sub_query_nodes (List[EvidenceNode]), evidence_graph (EvidenceGraph)
输出: List[EvidenceNode] (content_type="document_chunk")

初始化:
  - top_k = settings.RETRIEVAL_TOP_K (默认10)
  - score_threshold = 0.3 (相似度阈值)
  - 初始化OpenAIEmbeddings:
      embed_kwargs = {
          "model": settings.EMBEDDING_MODEL,
          "api_key": settings.OPENAI_API_KEY,
      }
      if settings.OPENAI_API_BASE:
          embed_kwargs["base_url"] = settings.OPENAI_API_BASE  # 支持GLM等兼容API
      self._embeddings = OpenAIEmbeddings(**embed_kwargs)

对每个sub_query_node执行:
  步骤1: 验证节点类型
    if sq_node.evidence.content_type != "sub_query":
        continue  # 跳过非子查询节点
  
  步骤2: 提取查询文本
    query_text = sq_node.evidence.content
  
  步骤3: 生成查询embedding
    query_embedding = await self._embeddings.aembed_query(query_text)
    # 返回List[float], 维度由embedding模型决定 (通常1536或768)
  
  步骤4: PGVector相似度搜索
    调用 vector_store.similarity_search():
      - query_embedding: 查询向量
      - top_k: 返回前k个结果
      - score_threshold: 最低相似度阈值
    
    SQL查询逻辑 (PGVector内部):
      SELECT 
        id, 
        content, 
        metadata,
        1 - (embedding <=> %s::vector) AS score
      FROM document_chunks
      WHERE 1 - (embedding <=> %s::vector) >= %s
      ORDER BY embedding <=> %s::vector
      LIMIT %s
      
      其中:
        - <=> 是PGVector的余弦距离操作符
        - %s::vector 是参数化查询, 防止SQL注入
        - score = 1 - cosine_distance (转换为相似度分数)
  
  步骤5: 封装检索结果为EvidenceNode
    对每个result (已按相似度排序):
      5.1 提取字段:
          score = result.get("score", 0.0)  # 相似度分数 [0, 1]
          content = result.get("content", "")
          doc_id = result.get("id", "")
          metadata = result.get("metadata", {})
      
      5.2 创建EvidenceNode:
          - content_type = "document_chunk"
          - content = content (文档片段文本)
          - source = doc_id
          - metadata = {
              "similarity_score": score,
              "doc_metadata": metadata,
              "rank": i  # 排名 (0-based)
            }
          - confidence = score (直接使用相似度作为置信度)
          - intent = IntentType.RETRIEVE
          - intent.parameters = {"similarity_score": score, "rank": i}
          - parent_node_ids = [parent_node.node_id]  # 连接到子查询节点
          - relation = EdgeRelation.DERIVED_FROM
          - tags = ["vector_result", f"rank_{i}"]
      
      5.3 添加到graph并收集到nodes列表
  
  步骤6: 异常处理
    如果检索失败:
      logger.error("vector_retrieval_failed", query=query_text, error=str(e))
      continue  # 跳过该子查询, 继续处理下一个

返回所有检索到的document_chunk节点
```

**关键配置项**:
- `RETRIEVAL_TOP_K`: 每个子查询返回的文档数量 (默认10)
- `EMBEDDING_MODEL`: Embedding模型名称
- `OPENAI_API_BASE`: API基础URL (支持GLM等兼容OpenAI API的服务)

**PGVector SQL细节**:
- 使用余弦距离操作符 `<=>` (PGVector扩展)
- 参数化查询使用 `%s::vector` 类型转换
- 相似度 = 1 - 余弦距离 (归一化到[0, 1])

### 1.4 KGRetriever 详细算法设计

**职责**: 通过知识图谱BFS遍历进行深度检索, 并将结果拆分为可读推理链.

**完整算法流程**:

```
输入: sub_query_nodes (List[EvidenceNode]), evidence_graph (EvidenceGraph)
输出: List[EvidenceNode] (content_type="kg_match" 或 "reasoning_chain")

初始化:
  - max_hops = settings.RETRIEVAL_KG_MAX_HOPS (默认3)
  - limit_per_hop = 15 (每跳限制节点数)
  - search_limit = 10 (初始搜索限制)

对每个sub_query_node执行:
  步骤1: 验证节点类型
    if sq_node.evidence.content_type != "sub_query":
        continue
  
  步骤2: 提取查询文本
    query_text = sq_node.evidence.content
  
  步骤3: Neo4j实体搜索 (find_entities)
    调用 neo4j_client.find_entities(text=query, limit=search_limit)
    
    Cypher查询逻辑 (Neo4j内部):
      MATCH (n)
      WHERE 
        (toLower(n.name) CONTAINS toLower($text) 
         OR toLower($text) CONTAINS toLower(n.name))
        OR (n.description IS NOT NULL 
            AND toLower(n.description) CONTAINS toLower($text))
      RETURN n, labels(n) AS labels, properties(n) AS properties, id(n) AS id
      LIMIT $limit
      
      匹配策略:
        - 双向CONTAINS: name CONTAINS query OR query CONTAINS name
        - 支持description字段搜索
        - 大小写不敏感 (toLower)
        - 返回节点ID, 标签, 属性
  
  步骤4: 创建直接匹配节点 (kg_match类型)
    对每个matched_node:
      4.1 提取字段:
          node_name = match.get("name", match.get("id", "unknown"))
          node_props = match.get("properties", {})
          node_labels = match.get("labels", [])
      
      4.2 构建可读内容:
          content_parts = [f"[{':'.join(node_labels)}] {node_name}"]
          if node_props.get("description"):
              content_parts.append(node_props["description"])
          for k, v in node_props.items():
              if k not in ("id", "name", "description") and v:
                  content_parts.append(f"  {k}: {v}")
          content = "\n".join(content_parts)
      
      4.3 创建EvidenceNode:
          - content_type = "kg_match"
          - content = content (格式化后的节点信息)
          - source = "knowledge_graph"
          - metadata = {
              "kg_node_id": match.get("id", ""),
              "kg_labels": node_labels,
              "rank": i
            }
          - confidence = max(0.6, 0.9 - i * 0.05)  # 按排名衰减
          - intent = IntentType.KG_EXPLORE
          - intent.parameters = {"kg_node_id": match.get("id", ""), "rank": i}
          - parent_node_ids = [parent_node.node_id]
          - relation = EdgeRelation.DERIVED_FROM
          - tags = ["kg_match", f"rank_{i}"]
      
      4.4 收集到result_nodes列表
  
  步骤5: BFS扩展 (从匹配节点出发)
    5.1 提取种子节点ID:
        matched_ids = [m.get("id") for m in matched_nodes if m.get("id")]
    
    5.2 调用BFS遍历:
        subgraph = await neo4j_client.bfs_traverse(
            start_node_ids=matched_ids,
            max_hops=max_hops,
            limit_per_hop=limit_per_hop
        )
        
        BFS Cypher查询逻辑 (Neo4j内部):
          # 第1跳: 从种子节点出发
          MATCH path = (start)-[*1..1]-(neighbor)
          WHERE id(start) IN $start_ids
          RETURN DISTINCT neighbor, relationships(path) AS rels
          LIMIT $limit_per_hop
          
          # 第2跳: 从第1跳结果出发
          MATCH path = (start)-[*2..2]-(neighbor)
          WHERE id(start) IN $start_ids
          RETURN DISTINCT neighbor, relationships(path) AS rels
          LIMIT $limit_per_hop
          
          # 第3跳: 从第2跳结果出发
          MATCH path = (start)-[*3..3]-(neighbor)
          WHERE id(start) IN $start_ids
          RETURN DISTINCT neighbor, relationships(path) AS rels
          LIMIT $limit_per_hop
          
          返回结构:
            {
              "nodes": [所有访问到的节点],
              "edges": [所有访问到的边],
              "depths": {node_id: depth}  # 每个节点的深度
            }
    
    5.3 构建推理链:
        chains = self._build_reasoning_chains(subgraph, seed_ids)
        
        推理链构建算法:
          for seed_id in seed_ids:
            # 找到种子节点
            chain_nodes = [n for n in nodes if n.get("id") == seed_id]
            # 添加连接的节点 (限制数量)
            remaining = [n for n in nodes if n.get("id") != seed_id]
            connected = chain_nodes + remaining[:limit_per_hop]
            
            if connected:
                chains.append({
                    "nodes": connected,
                    "seed": seed_id,
                    "depth": min(max_hops, len(connected))
                })
          
          如果没有任何链:
            # Fallback: 创建单链包含所有节点
            chains.append({
                "nodes": nodes,
                "seed": seed_ids[0] if seed_ids else "unknown",
                "depth": max_hops
            })
    
    5.4 将推理链转换为文本:
        chain_text = self._chain_to_text(chain)
        
        文本化算法:
          parts = []
          for node in chain.get("nodes", []):
              name = node.get("name", node.get("id", "?"))
              labels = node.get("labels", [])
              label_str = ":".join(labels) if labels else ""
              props = node.get("properties", {})
              desc = props.get("description", "")
              part = f"[{label_str}] {name}"
              if desc:
                  part += f" ({desc[:80]})"  # 截断描述
              parts.append(part)
          return " -> ".join(parts)  # 用箭头连接
    
    5.5 计算置信度:
        confidence = self._compute_chain_confidence(chain)
        
        置信度公式:
          depth = chain.get("depth", 1)
          confidence = 0.95 ^ max(depth, 1)
          
          原理: 跳数越多, 置信度越低 (指数衰减)
    
    5.6 创建推理链节点:
        - content_type = "reasoning_chain"
        - content = chain_text (如: "[Person]张三 -> [Company]昊中 -> [Product]AI系统")
        - source = "knowledge_graph"
        - metadata = {
            "chain_index": i,
            "chain_length": len(chain.get("nodes", [])),
            "seed_entities": seed_ids[:3],
            "depth": chain.get("depth", 0)
          }
        - confidence = confidence (计算出的置信度)
        - intent = IntentType.KG_EXPLORE
        - intent.parameters = {"chain_index": i, "max_hops": max_hops}
        - parent_node_ids = [parent_node.node_id]
        - relation = EdgeRelation.DERIVED_FROM
        - tags = ["kg_chain", f"depth_{chain.get('depth', 0)}"]
      
      5.7 收集到expansion_nodes列表
  
  步骤6: 合并结果
    result_nodes.extend(expansion_nodes)
  
  步骤7: 异常处理
    如果KG检索失败:
      logger.error("kg_retrieval_failed", query=query_text, error=str(e))
      continue

返回所有KG检索节点
```

**关键配置项**:
- `RETRIEVAL_KG_MAX_HOPS`: BFS最大跳数 (默认3)
- `limit_per_hop`: 每跳限制节点数 (默认15)
- `search_limit`: 初始实体搜索限制 (默认10)

**推理链拆分原理**:
- 目的: BFS返回的子图是复杂网络结构, 下游Agent难以理解
- 方法: 按种子实体分组, 每组提取一条从种子出发的线性路径
- 效果: 每条推理链是一个"故事线", Agent可以逐步理解多跳逻辑关系

### 1.5 CascadeFuser 详细算法设计

**职责**: 多轮迭代融合广度+深度检索结果, 识别信息缺口并持续优化.

**完整算法流程**:

```
输入: 
  - query (str): 原始用户查询
  - evidence_graph (EvidenceGraph): 证据图
  - breadth_nodes (List[EvidenceNode]): 向量检索结果
  - depth_nodes (List[EvidenceNode]): KG检索结果
输出: List[EvidenceNode] (content_type="fused_evidence")

初始化:
  - max_rounds = settings.RETRIEVAL_CASCADE_ROUNDS (默认3)
  - all_source_nodes = breadth_nodes + depth_nodes (合并所有源节点)
  - fused_nodes = [] (收集融合结果)

多轮融合循环 (for round_idx in range(max_rounds)):
  步骤1: 收集证据文本
    evidence_texts = self._collect_evidence_texts(all_source_nodes)
    
    收集算法:
      texts = []
      for node in nodes:
          content = node.evidence.content
          if content and content.strip():
              conf = node.belief.confidence
              texts.append(f"[confidence={conf:.2f}] {content}")
      return texts
    
    限制: 最多收集20个证据片段 (避免上下文过长)
  
  步骤2: LLM融合
    2.1 构建证据块:
        evidence_block = "\n---\n".join(evidence_texts[:20])
    
    2.2 加载System Prompt:
        SystemMessage: load_prompt("cascade_fusion_system")
        
        Prompt要求:
          - 评估证据相关性 (relevance_score)
          - 评估信息完整性 (completeness_score)
          - 识别信息缺口 (gaps)
          - 生成融合摘要 (fused_summary)
          - 提供推理过程 (reasoning)
    
    2.3 构建消息:
        HumanMessage: 
          "Query: {query}\n\nEvidence fragments:\n{evidence_block}"
    
    2.4 调用LLM:
        response = await llm_service.call(messages, prompt_name="cascade_fusion_system")
        content = response.content.strip()
    
    2.5 解析JSON输出:
        if "```" in content:
            content = content.split("```")[1]
            if content.startswith("json"):
                content = content[4:]
            content = content.strip()
        
        try:
            fusion_result = json.loads(content)
        except json.JSONDecodeError:
            # Fallback: 使用原始文本作为摘要
            fusion_result = {
                "fused_summary": content,
                "relevance_score": 0.5,
                "completeness_score": 0.5,
                "gaps": [],
                "reasoning": "Failed to parse structured output"
            }
        
        期望JSON结构:
          {
            "fused_summary": "融合后的证据摘要文本",
            "relevance_score": 0.0-1.0,
            "completeness_score": 0.0-1.0,
            "gaps": ["缺口1", "缺口2"],
            "reasoning": "融合推理过程"
          }
  
  步骤3: 创建融合节点
    3.1 计算融合置信度:
        completeness = fusion_result.get("completeness_score", 0.5)
        relevance = fusion_result.get("relevance_score", 0.5)
        combined_confidence = (completeness + relevance) / 2.0
    
    3.2 收集父节点ID:
        parent_ids = [n.node_id for n in all_source_nodes]
    
    3.3 创建EvidenceNode:
        - content_type = "fused_evidence"
        - content = fusion_result.get("fused_summary", "")
        - source = "cascade_fuser"
        - metadata = {
            "round": round_idx + 1,
            "relevance": relevance,
            "completeness": completeness,
            "gaps": fusion_result.get("gaps", []),
            "reasoning": fusion_result.get("reasoning", "")
          }
        - confidence = combined_confidence
        - intent = IntentType.CASCADE_FUSE
        - intent.parameters = {
            "round": round_idx + 1,
            "source_count": len(all_source_nodes),
            "gaps": fusion_result.get("gaps", [])
          }
        - parent_node_ids = parent_ids (所有源节点)
        - relation = EdgeRelation.FUSED_INTO (融合关系)
        - tags = ["fused", f"cascade_round_{round_idx + 1}"]
    
    3.4 添加到graph并收集到fused_nodes
  
  步骤4: 提前停止检查
    if completeness >= 0.85:
        logger.info("cascade_early_stop", round=round_idx + 1, completeness=completeness)
        break  # 信息完整性足够, 提前结束
  
  步骤5: 准备下一轮源节点
    # 将融合节点加入下一轮的源节点列表 (累积融合)
    all_source_nodes = [fused_node] + all_source_nodes

返回所有融合节点
```

**关键配置项**:
- `RETRIEVAL_CASCADE_ROUNDS`: 最大融合轮数 (默认3)
- Prompt文件: `app/prompts/cascade_fusion_system.md`

**融合策略**:
- 第1轮: 融合原始检索结果 (breadth + depth)
- 第2轮: 融合第1轮结果 + 原始结果
- 第3轮: 融合第2轮结果 + 之前所有结果
- 提前停止: 如果completeness >= 0.85, 不再继续融合

**完整算法流程**:

```
输入: query (str), evidence_graph (EvidenceGraph)
输出: List[EvidenceNode] (content_type="proposal")

  evidence_summary = self._summarize_evidence(high_conf_nodes)

        ctype = node.evidence.content_type

  evidence_stats = self._count_evidence_types(evidence_graph)

    counts: Dict[str, int] = {}

        counts[ct] = counts.get(ct, 0) + 1

  4.3 构建Human消息:

  4.6 异常处理 (Fallback):

    5.3 添加到graph并收集到proposal_nodes

步骤6: 记录日志

**与旧template模式的区别**:

| 维度 | 旧template模式 | 新slot-filling模式 |
|------|---------------|-------------------|
| proposal定义 | template文本模板 | slots槽位定义列表 |
| 生成方式 | LLM自由填充模板 | LLM从证据图提取信息到每个slot |
| 输出格式 | 任意文本 | 结构化JSON {slot_name: {value, confidence, sources}} |

### 2.3 ContentGenerator 详细算法设计 (Stage 2)

**类比**: Fast RCNN的ROI Head — 对每个proposal执行特征提取(而非自由生成)

**完整算法流程**:

```
输入: 
  - proposal_nodes (List[EvidenceNode]): Proposal节点列表
  - evidence_graph (EvidenceGraph): 证据图
  - query (str): 原始查询
输出: List[EvidenceNode] (content_type="generated_content")

步骤1: 按优先级排序Proposals
  sorted_proposals = sorted(
      proposal_nodes,
      key=lambda n: n.evidence.metadata.get("priority", 3)
  )
  # priority越小优先级越高 (1最高, 5最低)

对每个proposal_node执行:
  步骤2: 解析Proposal内容
    try:
        proposal = json.loads(proposal_node.evidence.content)
    except json.JSONDecodeError:
        # Fallback: 创建默认proposal结构
        proposal = {
            "aspect": "general",
            "question": proposal_node.evidence.content,
            "slots": [{"name": "content", "description": "Main content", "evidence_hint": "any"}]

    evidence_by_hint = self._gather_evidence_by_hint(evidence_graph, slots)

      all_nodes = list(evidence_graph.nodes.values())

      # 定义hint到tags的映射

                      n for n in all_nodes
                      if any(t in n.tags for t in matching_tags)

                  ]
              else:

                      n for n in all_nodes
                      if n.evidence.content_type not in ("proposal",)
                      and n.belief.confidence >= 0.2
                  ]
      
      return result
  
  步骤4: 格式化证据供LLM提取
    evidence_text = self._format_evidence_for_extraction(evidence_by_hint)
    
    格式化算法:
      parts = []
      for hint, nodes in evidence_by_hint.items():
          parts.append("=== Evidence type: %s ===" % hint)
          for n in nodes[:8]:  # 每种类型最多8个节点
              parts.append(
                  "[id=%s conf=%.2f] %s"
                  % (n.node_id[:8], n.belief.confidence, n.evidence.content[:250])
              )
          if not nodes:
              parts.append("(no evidence of this type)")
      return "\n".join(parts)
  
  步骤5: 构建LLM消息
    5.1 格式化slots描述:

        HumanMessage: (

      期望JSON结构:

              conf = slot_data.get("confidence", 0)

            "filled_slots": filled_slots,  # 完整JSON结构
            "slot_count": len(slots),
            "filled_count": filled_count,
            "evidence_count": evidence_count

        - intent = IntentType.GENERATE
        - intent.description = "Slot-filled content for: %s" % aspect
        - intent.parameters = {"aspect": aspect}
        - parent_node_ids = [proposal_node.node_id]  # 连接到proposal

    10.3 添加到graph并收集到generated_nodes
  
  步骤11: 异常处理
    如果提取失败:
      logger.error(
          "slot_extraction_failed",
          proposal_aspect=prop_node.evidence.metadata.get("aspect"),
          error=str(e)
      )
      continue  # 跳过该proposal, 继续处理下一个

步骤12: 记录日志

返回generated_nodes
```

- Prompt文件: `app/prompts/slot_extraction_system.md`

- 证据不足的slot: value=null, confidence=0

### 3.2 ScoringFunction 详细算法设计

**解决的问题**:
- 问题1: `cos(A, B) == cos(B, A)`, 但相关性是不对称的
- 问题2: 高维embedding空间中余弦相似度区分度差

**完整算法流程**:

```
输入:
  - query_embedding: List[float] (查询向量)
  - doc_embedding: List[float] (文档向量)
  - query_tokens: List[str] (查询分词)
  - doc_tokens: List[str] (文档分词)
输出: Dict[str, float] {
    "dense_score": float,
    "sparse_score": float,
    "combined_score": float,
    "asymmetry_factor": float
  }

步骤1: Dense组件 (去噪余弦相似度)
  dense_score = self._denoised_cosine(query_embedding, doc_embedding)
  
  去噪算法 (_denoised_cosine):
    1.1 转换为numpy数组:
        a = np.array(query_embedding, dtype=np.float64)
        b = np.array(doc_embedding, dtype=np.float64)
    
    1.2 验证维度:
        if a.shape != b.shape or a.size == 0:
            return 0.0
    
    1.3 自监督去噪:
        # 计算均值向量 (代表公共信息方向)
        mean_vec = (a + b) / 2.0
        mean_norm = np.linalg.norm(mean_vec)
        
        if mean_norm > 1e-10:
            # 归一化均值方向 (噪声方向)
            noise_direction = mean_vec / mean_norm
            
            # 去除噪声分量
            # λ = denoising_strength (默认0.1)
            a_denoised = a - self.denoising_strength * np.dot(a, noise_direction) * noise_direction
            b_denoised = b - self.denoising_strength * np.dot(b, noise_direction) * noise_direction
        else:
            a_denoised = a
            b_denoised = b
        
        原理:
          - 两个向量的均值方向代表它们共享的"公共信息"
          - 去除该方向的分量后, 保留的是区分性信息
          - 这提高了信号噪声比, 改善细粒度区分能力
    
    1.4 计算余弦相似度:
        norm_a = np.linalg.norm(a_denoised)
        norm_b = np.linalg.norm(b_denoised)
        
        if norm_a < 1e-10 or norm_b < 1e-10:
            return 0.0
        
        cosine = np.dot(a_denoised, b_denoised) / (norm_a * norm_b)
        return float(cosine)

步骤2: Sparse组件 (非对称BM25风格得分)
  sparse_score = self._sparse_score(query_tokens, doc_tokens)
  
  稀疏得分算法 (_sparse_score):
    2.1 边界检查:
        if not query_tokens or not doc_tokens:
            return 0.0
    
    2.2 计算文档词频:
        doc_tf = Counter(doc_tokens)  # 词频统计
        doc_len = len(doc_tokens)
        avg_dl = max(doc_len, 1)  # 平均文档长度 (简化: 单文档上下文)
    
    2.3 BM25参数:
        k1 = 1.2  # 词频饱和参数
        b = 0.75  # 长度归一化参数
    
    2.4 对每个查询词计算得分:
        score = 0.0
        
        for token in set(query_tokens):  # 去重
            tf = doc_tf.get(token, 0)  # 文档中该词的出现次数
            if tf == 0:
                continue  # 文档中没有该词, 跳过
            
            # 计算IDF (从查询角度)
            query_tf = query_tokens.count(token)  # 查询中该词出现次数
            idf = math.log(1 + 1.0 / max(query_tf, 1))
            
            # 词频越高, IDF越小 (查询词越常见, 权重越低)
            # 词频越低, IDF越大 (查询词越独特, 权重越高)
            
            # BM25 TF归一化
            tf_norm = (tf * (k1 + 1)) / (tf + k1 * (1 - b + b * doc_len / avg_dl))
            
            # 累加得分
            score += idf * tf_norm
    
    2.5 归一化到[0, 1]:
        max_possible = len(set(query_tokens)) * math.log(2) * (k1 + 1)
        if max_possible > 0:
            score = min(score / max_possible, 1.0)
        
        return score
    
    关键特性:
      - score(query, doc) ≠ score(doc, query) (非对称)
      - 因为IDF是从query角度计算的
      - 这打破了余弦相似度的对称性问题

步骤3: 计算非对称因子
  reverse_sparse = self._sparse_score(doc_tokens, query_tokens)
  asymmetry = abs(sparse_score - reverse_sparse)
  
  用途: 衡量得分的非对称程度

步骤4: 组合得分
  combined = self.dense_weight * dense_score + self.sparse_weight * sparse_score
  
  其中:
    dense_weight = 1.0 - sparse_weight
    sparse_weight = settings.EVALUATION_SPARSE_WEIGHT (默认0.3)
  
  因此:
    combined = 0.7 * dense_score + 0.3 * sparse_score

步骤5: 返回结果
  return {
      "dense_score": round(dense_score, 4),
      "sparse_score": round(sparse_score, 4),
      "combined_score": round(combined, 4),
      "asymmetry_factor": round(asymmetry, 4)
  }

批量计算 (batch_score):
  输入:
    queries: List[Dict[str, Any]] (每个dict有embedding和tokens)
    documents: List[Dict[str, Any]] (每个dict有embedding和tokens)
  
  输出: np.ndarray of shape (len(queries), len(documents))
  
  算法:
    n_q = len(queries)
    n_d = len(documents)
    matrix = np.zeros((n_q, n_d), dtype=np.float64)
    
    for i, q in enumerate(queries):
        for j, d in enumerate(documents):
            result = self.score(
                query_embedding=q.get("embedding", []),
                doc_embedding=d.get("embedding", []),
                query_tokens=q.get("tokens", []),
                doc_tokens=d.get("tokens", [])
            )
            matrix[i, j] = result["combined_score"]
    
    return matrix
```

**关键配置项**:
- `EVALUATION_SPARSE_WEIGHT`: 稀疏分量权重 (默认0.3, dense=0.7)
- `denoising_strength`: 去噪强度 (默认0.1)

**组合公式**:
```
combined = α × dense_denoised + (1-α) × sparse
α = 1 - EVALUATION_SPARSE_WEIGHT = 0.7
```

### 3.3 HungarianMatcher 详细算法设计

**类比**: DETR的二部图最优匹配

**完整算法流程**:

```
输入:
  - predictions: List[Dict[str, Any]] (生成内容, 每个dict有embedding/tokens/content/id)
  - targets: List[Dict[str, Any]] (证据源, 每个dict有embedding/tokens/content/id)
输出: Dict[str, Any] {
    "matches": List[Tuple[int, int, float]],  # (pred_idx, target_idx, score)
    "unmatched_preds": List[int],
    "unmatched_targets": List[int],
    "cost_matrix": List[List[float]],
    "score_matrix": List[List[float]],
    "overall_score": float
  }

步骤1: 边界检查
  n_pred = len(predictions)
  n_targ = len(targets)
  
  if n_pred == 0 or n_targ == 0:
      return {
          "matches": [],
          "unmatched_preds": list(range(n_pred)),
          "unmatched_targets": list(range(n_targ)),
          "cost_matrix": np.array([]),
          "overall_score": 0.0
      }

步骤2: 计算得分矩阵
  score_matrix = self.scoring_fn.batch_score(predictions, targets)
  
  矩阵维度: (n_pred × n_targ)
  每个元素 score_matrix[i, j] = ScoringFunction.score(pred_i, target_j)["combined_score"]

步骤3: 转换为代价矩阵
  cost_matrix = 1.0 - score_matrix
  
  原理: Hungarian算法最小化代价, 而我们需要最大化相似度
       因此 cost = 1 - similarity

步骤4: 执行Hungarian匹配
  from scipy.optimize import linear_sum_assignment
  
  row_indices, col_indices = linear_sum_assignment(cost_matrix)
  
  算法: 匈牙利算法 (Kuhn-Munkres算法)
    - 时间复杂度: O(n³)
    - 返回最优匹配: 每个pred最多匹配1个target, 每个target最多匹配1个pred
    - 最小化总代价

步骤5: 构建匹配结果
  matches: List[Tuple[int, int, float]] = []
  matched_preds = set()
  matched_targets = set()
  total_score = 0.0
  
  for row, col in zip(row_indices, col_indices):
      if row < n_pred and col < n_targ:
          match_score = float(score_matrix[row, col])
          matches.append((int(row), int(col), round(match_score, 4)))
          matched_preds.add(int(row))
          matched_targets.add(int(col))
          total_score += match_score

步骤6: 识别未匹配项
  unmatched_preds = [i for i in range(n_pred) if i not in matched_preds]
  unmatched_targets = [i for i in range(n_targ) if i not in matched_targets]

步骤7: 计算整体得分
  overall = total_score / max(len(matches), 1)
  # 平均匹配得分

步骤8: 返回结果
  return {
      "matches": matches,
      "unmatched_preds": unmatched_preds,
      "unmatched_targets": unmatched_targets,
      "cost_matrix": cost_matrix.tolist(),
      "score_matrix": score_matrix.tolist(),
      "overall_score": round(overall, 4)
  }

评估忠实度 (evaluate_faithfulness):
  输入:
    generated_sections: List[Dict[str, Any]]
    evidence_sources: List[Dict[str, Any]]
    threshold: float (默认0.5)
  
  输出: Dict[str, Any] {
      "faithfulness_rate": float,
      "section_scores": List[Dict],
      "unmatched_sections": List[int],
      "overall_score": float
    }
  
  算法:
    1. 执行匹配:
       result = self.match(generated_sections, evidence_sources)
    
    2. 评估每个匹配:
       faithful_count = 0
       section_scores: List[Dict[str, Any]] = []
       
       for pred_idx, targ_idx, score in result["matches"]:
           is_faithful = score >= threshold
           if is_faithful:
               faithful_count += 1
           
           section_scores.append({
               "generated_idx": pred_idx,
               "evidence_idx": targ_idx,
               "score": score,
               "is_faithful": is_faithful
           })
    
    3. 计算忠实度率:
       total = len(generated_sections)
       faithfulness_rate = faithful_count / max(total, 1)
    
    4. 返回结果:
       return {
           "faithfulness_rate": round(faithfulness_rate, 4),
           "section_scores": section_scores,
           "unmatched_sections": result["unmatched_preds"],
           "overall_score": result["overall_score"]
       }
```

**关键配置项**:
- `EVALUATION_CONFIDENCE_THRESHOLD`: 质量合格阈值 (默认0.7)

**Hungarian算法原理**:
- 二部图最优匹配问题
- 确保每个预测最多匹配1个目标, 每个目标最多匹配1个预测
- 最小化总匹配代价 (等价于最大化总相似度)

### 3.4 AutoPromptOptimizer 详细算法设计

**触发条件**: `overall_score < EVALUATION_CONFIDENCE_THRESHOLD`

**完整算法流程**:

```
输入:
  - evaluation_results: Dict[str, Any] (HungarianMatcher输出)
  - evidence_graph: EvidenceGraph
  - current_prompts: Optional[Dict[str, str]] (当前prompt模板)
输出: List[EvidenceNode] (content_type="prompt_optimization")

步骤1: 识别弱Section

  识别算法:
    weak = []
    section_scores = evaluation_results.get("section_scores", [])
    
    # 识别低分或非忠实的匹配
    for section in section_scores:
        if not section.get("is_faithful", True) or section.get("score", 1.0) < 0.5:
            weak.append({
                "section_idx": section.get("generated_idx"),

        weak.append({
            "section_idx": idx,
            "score": 0.0,

  if not weak_sections:
      logger.info("auto_prompt_no_weak_sections")
      return []

步骤3: LLM生成优化建议
  proposals = await self._generate_optimizations(weak_sections, current_prompts or {})
  
  生成算法 (_generate_optimizations):
    3.1 格式化弱Section摘要:
        weak_summary = json.dumps(weak_sections, indent=2)
    
    3.2 格式化当前Prompts (截断):
        prompt_summary = json.dumps(
            {k: v[:200] + "..." for k, v in current_prompts.items()},
            indent=2
        ) if current_prompts else "(no current prompts provided)"
    
    3.3 加载System Prompt:
        SystemMessage: load_prompt("auto_prompt_system")

          "You are a prompt optimization expert. Analyze weak sections from evaluation

           - diagnosis: what went wrong (missing context, wrong granularity, hallucination, etc.)
           - prompt_patch: specific modification to the prompt
           - expected_improvement: expected score improvement (0.0-1.0)
           - target: which prompt to modify (system_prompt, proposal_template, extraction_template)
           
           Output JSON array of optimization proposals."
    
    3.4 构建Human消息:
        HumanMessage: (
            f"Weak sections from evaluation:\n{weak_summary}\n\n"
            f"Current prompts (truncated):\n{prompt_summary}"
        )
    
    3.5 调用LLM:
        response = await llm_service.call(messages, prompt_name="auto_prompt_system")
        content = response.content.strip()
    
    3.6 解析JSON输出:
        if "```" in content:
            content = content.split("```")[1]
            if content.startswith("json"):
                content = content[4:]
            content = content.strip()
        
        try:
            parsed = json.loads(content)
            return parsed if isinstance(parsed, list) else [parsed]
        except json.JSONDecodeError:
            # Fallback: 将原始输出作为单个优化建议
            return [{
                "diagnosis": "parse_error",
                "prompt_patch": content,
                "expected_improvement": 0.3,
                "target": "general"
            }]
    
    期望JSON结构:
      [
        {
          "diagnosis": "Missing context in slot extraction",
          "prompt_patch": "Add instruction to consider all evidence types",
          "expected_improvement": 0.15,
          "target": "slot_extraction_system"
        },
        ...
      ]

步骤4: 创建优化节点
  optimization_nodes: List[EvidenceNode] = []
  
  for i, prop in enumerate(proposals):
    4.1 创建EvidenceNode:
        - content_type = "prompt_optimization"
        - content = json.dumps(prop, ensure_ascii=False)
        - source = "auto_prompt_optimizer"
        - metadata = {
            "diagnosis": prop.get("diagnosis", ""),
            "target": prop.get("target", ""),
            "expected_improvement": prop.get("expected_improvement", 0)
          }
        - confidence = prop.get("expected_improvement", 0.5)
        - intent = IntentType.OPTIMIZE_PROMPT
        - intent.description = f"Auto prompt optimization targeting {prop.get('target', 'unknown')}"
        - intent.parameters = {
            "target": prop.get("target", ""),
            "diagnosis": prop.get("diagnosis", "")
          }
        - tags = ["prompt_optimization", prop.get("target", "general")]
    
    4.2 添加到graph并收集到optimization_nodes

步骤5: 记录日志
  logger.info(
      "auto_prompt_proposals_generated",
      count=len(optimization_nodes)
  )

返回optimization_nodes
```

**关键配置项**:
- Prompt文件: `app/prompts/auto_prompt_system.md`

**诊断类别**:

- Wrong granularity: 粒度不合适
- Hallucination: 生成幻觉内容
- Insufficient evidence: 证据不足
- Extraction error: 提取错误

### 4.1 Gateway路由逻辑

**职责**: 中央路由节点, 唯一允许使用Command.goto的节点.

**完整路由算法**:

```
输入: state (PipelineState)
输出: Command[ROUTE_TARGETS]

步骤1: 提取状态信息
  phase = state.current_phase
  iteration = state.iteration_count
  max_iter = state.max_iterations
  rollback_count = state.rollback_count

步骤2: 安全检查 (硬迭代限制)
  if iteration >= max_iter:
      logger.warning("gateway_max_iterations_reached", iteration=iteration)
      return Command(
          update={"current_phase": PipelinePhase.DONE.value},
          goto="assemble_output"
      )

步骤3: 基于Phase的路由 (状态机)
  
  3.1 EXPLORE阶段:
      if phase == PipelinePhase.EXPLORE.value:
          return Command(
              update={"next_agent": "retrieval_agent"},
              goto="retrieval_agent"
          )
  
  3.2 FREEZE阶段:
      if phase == PipelinePhase.FREEZE.value:
          return Command(goto="freeze_context")
  
  3.3 PLAN阶段:
      if phase == PipelinePhase.PLAN.value:
          return Command(goto="plan_phase")
  
  3.4 EXECUTE阶段:
      if phase == PipelinePhase.EXECUTE.value:
          return Command(
              update={"next_agent": "generation_agent"},
              goto="generation_agent"
          )
  
  3.5 VALIDATE阶段:
      if phase == PipelinePhase.VALIDATE.value:
          return Command(
              update={"next_agent": "evaluation_agent"},
              goto="evaluation_agent"
          )
  
  3.6 ROLLBACK阶段:
      if phase == PipelinePhase.ROLLBACK.value:
          return _rollback_routing(state)
      
      回滚路由逻辑:
        if (rollback_count < max_rollbacks 
            and iteration < max_iterations - 3):
            # 可以回滚: 转到rollback_phase
            logger.info(
                "gateway_rollback_to_explore",
                rollback_count=rollback_count,
                feedback=state.validation_feedback[:100]
            )
            return Command(goto="rollback_phase")
        else:
            # 回滚次数耗尽: 组装最佳输出
            logger.warning(
                "gateway_exhausted_rollbacks",
                rollback_count=rollback_count,
                iterations=iteration
            )
            return Command(
                update={"current_phase": PipelinePhase.DONE.value},
                goto="assemble_output"
            )
  
  3.7 HUMAN_REVIEW阶段:
      if phase == PipelinePhase.HUMAN_REVIEW.value:
          return Command(
              update={"current_phase": PipelinePhase.DONE.value},
              goto="assemble_output"
          )
  
  3.8 DONE阶段:
      if phase == PipelinePhase.DONE.value:
          return Command(goto="assemble_output")

步骤4: 默认路由 (初始状态)
  return Command(
      update={"current_phase": PipelinePhase.EXPLORE.value},
      goto="retrieval_agent"
  )
```

**状态机转换**:
```
[*] --> EXPLORE       (检索: RAG + KG)
EXPLORE --> FREEZE    (快照context_manifest + evidence)
FREEZE --> PLAN       (proposal分解)
PLAN --> EXECUTE      (内容生成)
EXECUTE --> VALIDATE  (评估 + 打分)
VALIDATE --> DONE     (通过 -> 组装输出)
VALIDATE --> ROLLBACK (失败 -> 扩展/修复)
ROLLBACK --> EXPLORE  (重试with反馈)
```

              "aspect": "supporting_details",
              "question": "What additional context supports the answer?",
              "slots": [
                  {"name": "details", "description": "Supporting evidence details", "evidence_hint": "document_chunk"},
                  {"name": "reasoning", "description": "Reasoning chain if available", "evidence_hint": "kg_match"}
              ],
              "priority": 2
          },
          {
              "aspect": "summary",
              "question": "Brief conclusion?",
              "slots": [
                  {"name": "conclusion", "description": "Concise conclusion", "evidence_hint": "fused_evidence"}
              ],
              "priority": 3
          }
      ]

步骤6: 记录日志
  logger.info("plan_created", steps=len(plan_dag))

步骤7: 返回更新
  return {
      "plan_dag": plan_dag,
      "current_phase": PipelinePhase.PLAN.value
  }
```

**关键配置项**:
- Prompt文件: `app/prompts/plan_phase_system.md`

### 4.5 post_validate 详细算法

**职责**: 决定Done vs Rollback.

**算法流程**:

```
输入: state (PipelineState)
输出: Dict[str, Any] {"current_phase": str, ...}

步骤1: 提取评估结果
  eval_outputs = [
      o for o in state.agent_outputs
      if o.agent_name == "evaluation_agent"
  ]
  
  if not eval_outputs:
      return {"current_phase": PipelinePhase.DONE.value}
  
  latest_eval = eval_outputs[-1]  # 取最新的评估结果

步骤2: 获取得分
  overall_score = latest_eval.metrics.get("overall_score", 0.0)
  threshold = settings.EVALUATION_CONFIDENCE_THRESHOLD

步骤3: 判断是否通过
  if overall_score >= threshold:
      # 质量通过
      if settings.HITL_ENABLED:
          logger.info("post_validate_hitl", score=overall_score)
          return {"current_phase": PipelinePhase.HUMAN_REVIEW.value}
      else:
          logger.info("post_validate_pass", score=overall_score)
          return {"current_phase": PipelinePhase.DONE.value}

步骤4: 质量失败 - 检查是否可以回滚
  if state.rollback_count < state.max_rollbacks:
      logger.info(
          "post_validate_rollback",
          score=overall_score,
          threshold=threshold,
          rollback_count=state.rollback_count
      )
      
      # 生成反馈信息
      feedback = (
          f"Evaluation score {overall_score:.2f} below threshold {threshold}. "
          f"Weak areas: {json.dumps(latest_eval.metrics.get('section_scores', []), default=str)[:200]}"
      )
      
      return {
          "current_phase": PipelinePhase.ROLLBACK.value,
          "validation_feedback": feedback
      }
  else:
      # 回滚次数耗尽
      logger.warning(
          "post_validate_exhausted",
          score=overall_score,
          rollback_count=state.rollback_count
      )
      return {"current_phase": PipelinePhase.DONE.value}
```

**关键配置项**:
- `EVALUATION_CONFIDENCE_THRESHOLD`: 质量合格阈值 (默认0.7)
- `HITL_ENABLED`: 是否启用人工审核 (默认true)

### 4.6 rollback_phase 详细算法

**职责**: 准备回滚状态.

**算法流程**:

```
输入: state (PipelineState)
输出: Dict[str, Any] {
    "current_phase": str,
    "rollback_count": int
  }

步骤1: 记录日志
  logger.info(
      "rollback_triggered",
      rollback_count=state.rollback_count + 1,
      feedback=state.validation_feedback[:100]
  )

步骤2: 更新状态
  return {
      "current_phase": PipelinePhase.EXPLORE.value,  # 回到探索阶段
      "rollback_count": state.rollback_count + 1    # 递增回滚计数
  }
  
  注意: validation_feedback会自动保留在state中,
       检索Agent可以读取并调整策略
```

### 4.7 assemble_output 详细算法

**职责**: 组装最终输出.

**算法流程**:

```
输入: state (PipelineState)
输出: Dict[str, Any] {
    "messages": List[AIMessage],
    "final_output": str,
    "current_phase": str
  }

步骤1: 收集生成内容节点
  evidence_graph = state.evidence_graph
  
  generated = [
      n for n in evidence_graph.nodes.values()
      if n.evidence.content_type == "generated_content"
  ]
  
  如果没有生成内容, 使用融合证据作为后备:
    if not generated:
        generated = [
            n for n in evidence_graph.nodes.values()
            if n.evidence.content_type == "fused_evidence"
        ]

步骤2: 按优先级和置信度排序
  generated.sort(
      key=lambda n: (
          n.evidence.metadata.get("priority", 99),  # 优先级越小越前
          -n.belief.confidence                      # 置信度越大越前
      )
  )

步骤3: 组装文本
  sections = []
  for node in generated:
      content = node.evidence.content
      sections.append(content)
  
  final_text = "\n\n".join(sections) if sections else "No output generated."

步骤4: 创建响应消息
  response_message = AIMessage(content=final_text)

步骤5: 记录日志
  logger.info(
      "output_assembled",
      sections=len(sections),
      total_length=len(final_text)
  )

步骤6: 返回更新
  return {
      "messages": [response_message],
      "final_output": final_text,
      "current_phase": PipelinePhase.DONE.value
  }
```

### 5.2 Prompt加载器详细设计

**完整算法流程**:

```
模块: app/prompts/__init__.py

函数1: _read_prompt_file(name: str) -> str
  职责: 从磁盘读取prompt文件 (带LRU缓存)
  
  算法:
    1.1 构建文件路径:
        _PROMPT_DIR = Path(__file__).parent
        path = _PROMPT_DIR / f"{name}.md"
    
    1.2 检查文件存在:
        if not path.exists():
            raise FileNotFoundError(f"Prompt file not found: {path}")
    
    1.3 读取文件:
        return path.read_text(encoding="utf-8").strip()
    
    1.4 LRU缓存:
        @lru_cache(maxsize=64)
        def _read_prompt_file(name: str) -> str:
            ...
        
        缓存策略:
          - 最大缓存64个prompt文件
          - 自动淘汰最少使用的条目
          - 提高重复加载性能

函数2: load_prompt(name: str, **kwargs: Any) -> str
  职责: 加载并格式化prompt模板
  
  算法:
    2.1 加载模板:
        template = _read_prompt_file(name)
    
    2.2 格式化 (如果提供kwargs):
        if kwargs:
            try:
                return template.format(**kwargs)
            except KeyError as e:
                logger.warning(
                    "prompt_format_key_missing",
                    prompt=name,
                    missing_key=str(e)
                )
                return template  # 返回未格式化的模板
    
    2.3 返回结果:
        return template

函数3: reload_prompts() -> None
  职责: 清除prompt缓存, 强制从磁盘重新读取
  
  算法:
    _read_prompt_file.cache_clear()
    logger.info("prompt_cache_cleared")
  
  用途:
    - 开发时热重载prompt文件
    - 测试时重置缓存状态
```

### 5.3 Prompt文件内容

**query_decompose_system.md**:
```
You are a query decomposition specialist. Given a complex query,
break it into independent sub-queries that together cover all aspects of the original query.

Rules:
1. Each sub-query should be self-contained and searchable independently.
2. Sub-queries should be diverse - avoid redundancy.
3. Preserve the original intent in every sub-query.
4. Return 2-{max_sub_queries} sub-queries depending on complexity.

Output format: JSON array of objects with "query" and "aspect" fields.
Example: [{{"query": "...", "aspect": "temporal"}}, {{"query": "...", "aspect": "causal"}}]
```

**proposal_decompose_system.md**:
```
You are a content planning expert. Given a user query and retrieved evidence,
decompose the answer into multiple same-structured 'proposals'.

Each proposal is a SLOT-FILLING task (NOT a template to be written from scratch):
- aspect: what aspect to address (e.g. definition, components, applications)
- question: the specific question for this aspect
- slots: list of information slots to EXTRACT FROM EVIDENCE, each with:
  - name: slot name
  - description: what info to extract
  - evidence_hint: which evidence type (fused_evidence, kg_match, document_chunk)
- priority: 1 (highest) to 5 (lowest)

All proposals share the SAME STRUCTURE. Output JSON array. Max {max_proposals} proposals.
```

**slot_extraction_system.md**:
```
You are an evidence extraction specialist.

Given a proposal with slots and retrieved evidence, fill each slot
by EXTRACTING relevant information from the evidence ONLY.

Rules:
- Each slot must be filled using the provided evidence.
- If evidence is insufficient for a slot, set its value to null
  and set confidence to 0.
- Do NOT hallucinate or invent information.
- Be precise and factual.

Output: JSON object with slot_name as key, each value is:
  {{"value": "extracted text", "confidence": 0.0-1.0, "source_evidence_ids": []}}

The source_evidence_ids should reference the evidence IDs you used.
```

**plan_phase_system.md**:
```
You are a content planning specialist. Output valid JSON only.
```

**cascade_fusion_system.md**:
```
You are an evidence fusion specialist. Given multiple evidence fragments,
fuse them into a coherent summary.

Output JSON with:
- fused_summary: coherent summary of all evidence
- relevance_score: 0.0-1.0, how relevant to the query
- completeness_score: 0.0-1.0, how complete the information is
- gaps: list of information gaps identified
- reasoning: your fusion reasoning process
```

**auto_prompt_system.md**:
```
You are a prompt optimization expert. Analyze weak sections from evaluation
and propose specific prompt improvements.

For each weak section, provide:
- diagnosis: what went wrong (missing context, wrong granularity, hallucination, etc.)
- prompt_patch: specific modification to the prompt
- expected_improvement: expected score improvement (0.0-1.0)
- target: which prompt to modify (system_prompt, proposal_template, extraction_template)

Output JSON array of optimization proposals.
```

用户查询

    ↓

    ↓
[Gateway] → EXECUTE
    ↓
[GenerationAgent]
    ├─→ ProposalDecomposer (生成proposals)
    └─→ ContentGenerator (填充slots)
    ↓
[Gateway] → VALIDATE
    ↓
[EvaluationAgent]
    ├─→ ScoringFunction (去噪+稀疏得分)

        ↓

    ↓

```

## 8. 关键设计原则

1. **同结构Proposal**: 所有proposal共享相同slot结构, 确保粒度一致性
2. **证据提取优先**: LLM从证据图提取信息, 而非自由生成
3. **可追溯性**: 每个slot关联source_evidence_ids, 支持溯源
4. **非对称评分**: 打破余弦相似度对称性, 提高评估准确性
5. **自动优化**: 基于评估结果自动优化prompt, 减少人工干预
6. **状态机编排**: 清晰的阶段转换, 支持回滚和重试
7. **Prompt热重载**: LRU缓存 + reload接口, 支持开发时快速迭代
